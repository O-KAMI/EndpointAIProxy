# 单终端策略覆盖（工作树接口说明）

只对指定已注册、未撤销的 v2 终端覆盖网关和白名单。
域名分流扩展的本机 MySQL、浏览器验证及发布前待验项见 [DOMAIN-ROUTING.md](DOMAIN-ROUTING.md)，不是生产发布通过结论。
停用/启用继续使用现有远程命令。

全局策略 `enabled=false` 与远程停用命令的行为不同：现有客户端会拒绝代理
请求，但不会因此自动恢复已接入应用的配置，可能造成业务中断。需停用代理并
恢复配置时，应使用远程停用命令并核对执行回执；旧版客户端及真实平台恢复
效果仍须按发行验收验证。

控制台在心跳间隔超过 60 秒时提示并确认潜在时效风险；API 仍保留 15–3600 秒
的兼容范围，不强制改写既有策略。即使为 60 秒，网络、校准和服务端负载仍可能
影响 120 秒目标，必须通过真实终端及隔离负载验收。

## 管理接口

沿用管理员认证，路径为 `/admin/v1/devices/{deviceId}/policy`。

- GET 返回 `deviceId`、`globalPolicyVersion`、`hasOverride`、`overrides`、`effectivePolicy`。
- PUT 使用 `expectedVersion` 和 `overrides` 替换此终端的全部覆盖项。
- DELETE 使用 `expectedVersion` 恢复继承全局策略。

expectedVersion 必须匹配刚读取的 effectivePolicy.policyVersion，否则返回 409。
未注册/已撤销终端返回 404，管理员认证失败返回 401。
覆盖接受 routeMode、gatewayOrigin、allowInsecureGateway、allowlistedBaseUrls、allowlistedDomains、routingRules。
省略字段持续继承全局策略；白名单空数组表示该终端没有白名单。
除 gatewayOrigin 外，不接受显式 null；不接受未知字段。
合并后的完整策略沿用既有网关和白名单校验。

控制台资产详情新增“仅此终端的代理策略”，明确显示 Device ID。
进入详情自动加载后编辑；各覆盖项独立启用，保存冲突保留草稿，自动刷新详情不会覆盖草稿。
切换终端清空旧表单并忽略迟到响应；新客户端能力及应用状态单独展示。

## 版本与兼容

0.1.25 基线使用 schema 3 表 device_policy_state，保存覆盖、基础全局版本及有效策略快照。
本次域名扩展复用其 JSON 字段，不再新增表；策略正文 schema 2 独立于数据库版本。
所有版本分配先锁定全局策略单行，再锁终端策略行。
单终端更新不修改全局策略内容、版本或其他终端的响应。
全局更新分配高于所有已分配终端版本的版本；终端下次查询时重新合并继承字段。
若全局变更会使已有终端覆盖合并成无效策略，拒绝变更并回滚事务。

恢复继承保留更高的终端版本记录，避免客户端忽略旧版本。
v2 策略查询与心跳使用同一有效策略，签名仍针对实际响应正文。
v1 继续接收全局策略。分析按各终端应收到的版本计算应用状态。

## 迁移与回退门禁

仅支持精确 checksum 匹配的 schema 1/2 输入。停止全部应用实例后，使用既有
manage.py migrate-db 的 --service-stopped 维护入口；不会自动迁移，不使用 init-db 升级。
新增表并核验字段、唯一键后才更新版本标记，保留策略、凭据和业务记录。
部署前必须完成一致性数据库备份、可恢复性验证、隔离 MySQL 迁移及并发回归。

schema 2 旧应用不能直接连接已迁移的 schema 3 数据库。
尚未下发任何终端策略时，可使用已核验的协调器解除空表和 schema 标记的新增变更；不覆盖业务表。
一旦存在终端版本记录，拒绝回退旧代码，须保留 schema 3 修复新版；不能改版本标记或丢弃记录。
现场下发仅限目标终端，并核对全局策略和非目标终端未变化。
