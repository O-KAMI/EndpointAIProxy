# 控制端 0.1.26 候选验收状态

**未通过发行验收，未部署生产。** 源码包含 schema 5、策略和命令批次、
客户端同步、管理查询及认证等优化；本机合成测试不证明 Linux 发行或容量。
完整实现与测试范围见 [规模实施记录](SCALE-IMPLEMENTATION-20261028.md)，
整体交接见 [优化结果](../../docs/SCALE-OPTIMIZATION-RESULT-20261029.md)。

发行前至少完成：隔离 Linux 环境的 schema 3/4→5、备份恢复、升级回退、
多进程和故障注入；两种 Linux 架构的离线依赖原生安装与最终包校验；15 万设备
存量、10 万在线混合负载、重连尖峰、策略收敛及 **8 小时长稳**。所有结果绑定
最终发行包摘要。用户没有服务器 root 权限，依赖目标环境现有受管入口和运维支持。

现有 `scale_inventory_probe.py` 是数据库单项合成实验，`go-client/scripts/soak.py`
是单客户端与模拟控制面的长稳工具；两者均不能生成或证明 10 万终端的完整 HTTP
混合负载。执行容量门禁前还需准备并验证能够模拟旧版全量上报、新版轻量同步、
策略发布、重连和管理访问的隔离压测方案，记录发生器是否成为瓶颈及服务端指标。

`tools/load_transport.py` 是正在开发的隔离负载工具的通信基础：仅支持显式
127.0.0.1 HTTP 地址，使用固定公开合成密钥和令牌，并验证合成策略签名后才
允许发送请求。`tools/load_devices.py` 提供合成 v1/v2 心跳和有界并发建档、全量
基线；小样本本机隔离 MySQL 与真实 HTTP 互通通过。`load_schedule.py` 和
`load_run.py` 增加了错峰心跳、策略拉取及发生器积压统计；旧版周期策略轮询
与心跳独立调度，并支持合成集中启动尖峰。可选合成策略发布并统计模拟设备版本上报时间；
该统计不代表真实终端配置校准。可选单台 v2 合成命令并统计模拟回执耗时，
不改变实际终端配置。增加并发设备列表查询和查询遗漏统计；每次合成管理操作
额外执行一次合成端点证明。可选模拟离线停发并在恢复时错峰重连，单独统计离线
期间未发事件；这不是实际网络故障注入。可选采样 Linux 指定进程的 CPU、内存、
句柄和本地磁盘，但尚未在 Linux 原生验证，也不采集远程 MySQL。合成本地账号、
HTTPS 和命令批次已在本机小样本验证；尚未覆盖完整服务器及数据库指标，
也尚无完整长稳和容量报告，不能用于推广验收；
这些公开合成凭据不得配置到生产服务。该约束不证明目标主机本身已隔离。
现有开发中入口及限制见 [隔离负载工具说明](ISOLATED-LOAD-TOOL.md)；本机六台
合成设备、真实 HTTP 和隔离 MySQL 的短时贯通通过，不能外推至 Linux 容量。
