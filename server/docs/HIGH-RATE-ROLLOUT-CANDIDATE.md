# 高速命令批次候选：仅供隔离验收

现网保持默认上限 20 台/秒。候选代码允许在独立隔离环境通过进程环境变量 `SF_CONTROL_ROLLOUT_MAX_RATE` 设置 1～5000 的每批次上限；值高于 20 才使用批量事务。管理进程和所有客户端接口工作进程必须使用同一候选代码和相同上限。启动 schema 检查会验证待处理索引完整且可见；缺失时高速配置不能通过检查。

每次事务最多处理 250 台，逐设备锁定、检查已有活动命令、写入命令和审计，并原子更新目标；暂停请求等待当前事务提交后阻止后续批次。速率是每个批次的长期平均上限，允许最多一批突发，多个并行批次的速率相加，数据库处理时间也会降低实际速率。降低配置上限后，速率超限的运行中批次会暂停并留审计，暂停批次也不能在超限时恢复。已发出的命令仍可能执行，超时结果未知的命令不可自动重执行。

隔离 MySQL 上可运行 `python server/tools/rollout_batch_probe.py --confirm-isolated --devices 100000 --rate 5000 --timeout 600 --profile`。工具只连接 127.0.0.1，创建并删除随机 `eai_batch_probe_` 测试库，数据库账号需有该前缀下的建库、维护和删库权限，可通过 `ENDPOINTAI_TEST_MYSQL_USER` / `ENDPOINTAI_TEST_MYSQL_PASSWORD` 从受保护的进程环境提供；这些不是 Linux 系统 root 权限。必须先确认实例、端口、目录和网络完全隔离，不得连接生产或通过隧道连接真实数据。工具只测数据库目标创建和命令入库，不执行真实终端命令。

本机隔离 MySQL 8.0.28 单次 10 万合成目标，显式设置每批 5000 台/秒：创建目标快照约 6.728 秒，命令及逐台审计入库约 54.806 秒，10 万条均记录。无 HTTP、并发心跳、远程数据库链路、终端执行和回执；这不是 120 秒端到端收敛验收。旧查询计划的对照为约 104 秒，但两次是单次实验，机器及缓存状态可能不同。

工具可选 `--heartbeat-workers 8 --heartbeat-rps 1000`，并发更新合成设备的心跳行，记录实际完成次数、调度遗漏和更新延迟。这只模拟一条数据库行更新及其锁竞争，不包含完整心跳事务、HTTP、加密、资产处理或终端，不能作为容量验收。本机隔离 MySQL 单次 1 万目标试验中，命令和审计均为 1 万条，下发约 9.484 秒；请求每秒 1000 次行更新，完成 6605 次、遗漏 2848 个调度，完成更新 p95 约 18.1 毫秒。生成器与数据库共用本机，该结果不能区分生成器瓶颈和数据库瓶颈，也不能外推到服务器。若工作线程无法停止，工具保留测试库，避免在活动连接上删库。

在真实混合负载、多个并发批次、限流冲击、数据库锁等待、恢复及 8 小时长稳通过前，不要提高现网配置。即使纯下发耗时低于 120 秒，终端的下一次心跳、配置恢复和回执仍占用时间，必须单独按 99% 目标核验。
