# 控制端隔离负载工具（开发中）

仅供独立隔离环境使用，不得配置到生产。控制端必须使用全新合成数据库和公开
合成凭据；工具只连接本机 `127.0.0.1`，并在工作线程和管理客户端初始化时验证
合成策略签名。回环地址及合成凭据校验不能证明主机没有承载生产服务，操作者
必须先确认机器、数据库、端口、数据目录及网络与生产隔离。

待测服务需要在隔离配置中使用以下固定**公开测试值**，切勿用于生产：

- 客户端令牌：`isolated-load-enrollment-token`
- 可选 legacy 管理令牌：`isolated-load-admin-token`，禁止暴露外网
- 本地账号模式：仅在隔离服务创建角色为 admin 的合成账号 `synthetic-load-admin`，
  密码 `synthetic-load-admin-password-only`；均为公开测试值，不得用于生产
- 传输密钥 ID：`isolated-load-fixture-v1`
- 传输密钥及策略 HMAC 密钥：Python `base64.b64encode(bytes(range(32))).decode()` 的结果

从 `server` 目录执行 `python -m tools.load_test --help` 查看参数。下例中的
端口、候选文件、私有目录及 PID 均为占位，需按隔离环境替换；输出文件必须是
不存在的新文件。Windows 下输出目录 ACL 需由操作者预先限制：

```sh
python -m tools.load_test --confirm-isolated --origin http://127.0.0.1:18080 \
  --devices 150000 --online 100000 --legacy 10000 --full-v2 10000 --seconds 28800 --workers 64 \
  --heartbeat-seconds 60 --event-devices 10000 --event-every 60 \
  --admin-query-seconds 10 --publish-after 300 \
  --command-after 600 --outage-after 1800 --outage-seconds 60 --reconnect-spread 60 \
  --pid 12345 --monitor-generator --disk-path /isolated/data \
  --server-artifact /isolated/candidate.tar.gz --output /isolated/private/run.jsonl
```

工具先以有界并发逐台建立全量资产基线，可能耗时很长并产生较大数据库负载；
出现错误时不重试注册。需由隔离环境操作者检查失败记录并处置测试数据库，
不能对生产库运行清理或以重新注册掩盖问题。正式测量计时从建档完成后开始。
`--legacy` 表示 v1 终端数，`--full-v2` 表示不使用轻量心跳和无状态策略版本的
旧 v2 终端数，其余在线 v2 为新版轻量路径；数量示例只是合成假设，应按实际
版本分布设置。旧 v2 全量上报并周期查询 schema 1 策略。
可单独运行集中启动场景：`--startup-spread 0 --startup-full` 让首轮心跳和旧版
策略轮询同时计划发送，新版 v2 首轮上报完整资产并拉取策略。具体启动窗口应另按
现场部署批次设置；发生器来不及发送的请求会计入遗漏，不能当作实际已发流量。

报告首行是 `running`，建档阶段每 1,000 台及完成时追加 `seeding`，发压阶段按
`--progress-seconds`（默认 60 秒）追加 `progress`，正常结束追加 `finished`，
异常追加不含原始异常内容的 `failed`。没有 `finished` 的中断报告不能当作通过。
报告包含候选材料摘要，但**不会自动
证明正在运行的服务来自该材料**；应独立记录进程、发布材料和配置的对应证据。
报告记录预期、已发、忙碌遗漏、离线压制事件及延时分桶；legacy 管理请求每次附带
合成端点校验，本地账号模式复用会话；旧版策略轮询独立错峰，新版按心跳版本变化
拉取，均会影响负载形态。模拟命令和策略回执不能
证明真实终端执行成功；停发与重连也不等于真实网络故障注入。
新版 v2 合成终端获得更高策略版本后，会在 0–5 秒随机安排一条轻量回执心跳，
并计入心跳请求与发生器遗漏。模型保留原周期心跳，因此较真实客户端重排下一次
心跳更保守；它不执行真实配置校准或终端资产扫描。报告单列计划、派发与遗漏数，
没有该模型标识的旧报告或没有计划补报的运行，补报负载检查为待验证。
模拟断网开始时，尚未发送且计划在恢复前发生的回执会重新安排到恢复后的错峰窗口；
与周期心跳撞车或未能在截止时间前派发时，仍会计入忙碌遗漏或未派发数量。断网
之前已经在执行的请求不会被工具强制中断，这仍不是实际网络故障注入。
评估器按新版 v2 在线设备去重，要求至少 99% 已安排针对本次发布版本的补报；
同一设备多次安排不扩大设备覆盖数。计划数及去重覆盖数只表明发生器的工作量，
请求错误和真实终端执行仍须由其他检查及独立验收判断。缺少覆盖字段的旧报告
不能通过此项检查。
延迟分桶排除传输失败，单次超过 60 秒时封顶；必须结合错误数和发生器遗漏一起分析。
测试截止后才收到的响应仍保留在延迟和诊断统计中，但不会计入窗口内的策略或命令
回执；心跳在截止后完成的数量单独记录。发布失败或策略回执计数不一致时，策略
收敛门禁为待验证。策略回执的 120 秒从发起发布请求开始计时，包含发布请求耗时；
旧报告没有该计时起点标识，评估器将其收敛结果标为待验证。
`--monitor-generator` 会将发生器本进程纳入 Linux 资源采样，报告中的 PID 用于区分
发生器和服务端；服务器和 MySQL 若在远端，仍需分别采集其资源。
评估器单独检查 `resource_sample_coverage`：报告必须记录采样 PID，采样线程正常
结束且未达到上限；所有样本均有各 PID 的进程标识、内存、CPU、线程和文件描述符
及磁盘容量和 inode；样本跨度至少 28,770 秒、相邻间隔不超过 30 秒，且不能出现
进程缺失或重启。该项仅检查采样覆盖，不判断资源趋势、余量或实际服务身份；要
确保填入全部服务工作进程及发生器，并另行采集远端数据库。旧报告缺少 PID 清单
时该项为待验证。Linux 真实采样仍需隔离环境验收。
控制服务每个工作进程约每分钟记录 `REPLAY_MAINTENANCE_METRICS`：`deleted`
是该进程本次统计间隔内删除的记录数，`oldestExpiredSeconds` 是数据库中最早
过期记录的逾期秒数，没有过期记录时为 0。多进程的删除数可按进程累加，逾期
秒数是同一数据库的采样，不应相加；采样失败另有错误日志，不能当作 0。压测
期间持续增长表示清理落后，须结合数据库资源和过期记录数量检查。
控制 API 的 `CONTROL_FAILURE_AGGREGATE` 逐进程、按分钟及路由/状态/错误码统计失败次数、
耗时总和与最大值；每组每分钟保留前 5 条详细请求样本。控制 API 未处理异常按
安全异常元数据另行统计 `CONTROL_EXCEPTION_AGGREGATE`，每组保留前 5 条样本，
最多 256 组，超出部分合并为 `OTHER`；管理接口及后台异常日志不在此限制内。
业务内部请求与外层加密入口分别计数，不能把两者相加当作失败终端数。进程异常退出
可能丢失尚未刷新的窗口；需按进程采集并结合发生器、入口及数据库指标核验，不能用
日志样本条数计算错误率。实际异常日志量、采集与告警仍需在隔离长稳中验证。
错误码只记录代码内固定白名单；未知或未标注的原因记为 `OTHER`，不能据此认定原因相同。
异常汇总与请求失败汇总是不同维度，不能相加计算失败次数；日志不会包含异常消息或局部变量。

`python -m tools.load_fixture_probe --requests 5000` 仅测本机生成和加密合成请求，
不连接服务，不包括 HTTP、解密响应或数据库，不能用作容量测试或单独证明发压能力。

本机一次发生器调度实验使用 10 万个同时到期的合成设备、128 个工作线程、3 秒
窗口及即时内存响应，未连接控制服务、网络或数据库；记录计划 103,000 次
心跳（含 3,000 次补报）、已派发 11,112 次、遗漏 91,888 次，其中 3,000 次
计划补报均未派发。结果仅说明该机器与参数下发生器未跟上此集中启动尖峰，不是
服务器吞吐或容量测试。正式隔离测试必须提供足够的独立发压资源，且以发生器
遗漏及资源监控为门禁；多个分片即使经下面的检查汇总，也不能视为全局时效与容量通过。

事件设备数和周期必须以实际终端事件分布确定；合成事件跟随心跳，不模拟独立
事件突发。可使用 `--admin-origin https://127.0.0.1:端口 --admin-ca 测试CA路径`
切换到合成本地账号及受信任 HTTPS 入口，并使用 `--rollout-after 秒数
--rollout-targets 目标数 --rollout-rate 每秒数量` 创建并恢复合成命令批次。
默认批次速率上限为 20 台/秒；隔离环境可按 [高速候选说明](HIGH-RATE-ROLLOUT-CANDIDATE.md)
显式配置更高上限并用 `--rollout-rate` 测试。配置的是每批平均速率，单批允许突发且多个批次叠加；不能据此声称 120 秒全部生效。模拟回执通过服务端批次目标游标逐一匹配命令 ID；核验失败
时不输出已核验数量。服务端批次状态和计数另行记录。集中启动为合成模型，工具尚未
覆盖完整主机和远程 MySQL
资源指标；Linux 资源采样尚未原生验收。`duration8hCompleted` 仅描述本次计时，
`capacityAcceptance` 始终为 `not evaluated`。需要额外验证发生器 CPU/网络瓶颈、
控制端和数据库完整指标、真实终端回执及全部验收门禁，才能评价推广容量。

运行结束后可用 `python -m tools.load_evaluate /isolated/private/run.jsonl` 对已有
报告做保守检查，包括规模、8 小时时长、发压缺口、心跳/策略/事件的延迟和错误、
模拟策略回执、合成命令批次回执及管理查询。批次时效从发起创建请求开始，分母
是该次批次的目标快照，单独报告；目标子集达标不代表所有在线终端达标。批次
结果缺少游标核对、计时起点或目标计数时为待验证，真实终端执行仍需单独验证。
对应接口没有请求或耗时样本不完整时为待验证。若回执
低于 99% 而发起策略发布请求后观察不足 120 秒，结果为待验证而非失败。
延时按毫秒向下分桶，因此阈值采用严格小于。该检查只覆盖所列指标，始终保留
真实终端、运行材料绑定、Linux、数据库和其他 API 的未完成项，不能作为推广批准。


评估器还会核对心跳周期不超过 60 秒、运行参数与报告一致，并按启动错峰及在线数
计算保守的最低计划心跳数；策略回执触发的额外心跳不会抵充周期工作量。旧版和
完整 v2 设备的定期策略轮询也需达到对应最低计划数。缺少这些字段、计划不足或
包含断网阶段时，该次运行的持续基线工作量标为待验证；断网重连应另作为故障场景
验收。上述数量校验不能单独证明每台终端均匀运行、发生器没有瓶颈或目标容量达标。
旧报告若不包含必要字段，需要重新运行才能获得相应证据。


## 合成设备区间与计划开始时间（基础能力）

可为每个独立发生器指定 `--ordinal-start`，结合 `--devices` 形成左闭右开的编号区间；区间总范围必须在 0–149999 内，操作者须事先验证所有区间不重叠。每个区间内的旧版设备数由该进程自己的 `--legacy` 和 `--full-v2` 指定；只运行每个区间前 `--online` 台，不可简单假定设备在线分布与实际相同。心跳、事件、策略和命令目标使用相同的全局合成设备标识。

可传入相同的 `--start-at 2026-11-01T12:00:00Z`，先分别建档；完成后报告写入 `ready` 并等待该 UTC 时间。如果建档完成时计划时间已过，报告以 `failed` 结束，必须重新准备隔离测试。最终记录实际 UTC 开始时间和相对计划的秒数；它依赖各主机系统时钟，不能证明时钟精度或机器间同步。需要预留足够建档时间、检查各进程的 `ready`、独立校验时钟误差，并监控进程直到最终记录。

## 单次发布事件与保守汇总（候选）

分片可以通过各机器均可访问的**隔离私有共享目录**交换单次策略发布事件。事件只含合成运行标识、候选文件摘要、计划开始时间、策略版本及发布前后时间，不含设备 Token；目录和报告仍须限制访问并保持完整性。共享文件不是经过认证的消息通道，操作者必须核实存储与各机器和生产隔离，保证只有测试账号可写；工具不负责创建共享设施。各机时钟及其误差必须独立核验，文件时间戳不能证明同步。

操作者先为本次实验生成新的 UUID，选定未来 UTC 开始时间及不同编号区间，准备相同摘要的候选文件。主分片使用 `--coordination-id UUID --start-at UTC --publish-after 秒数 --publish-event 共享目录/新文件`，其他分片使用相同 UUID、开始时间和候选摘要，并设置 `--follow-event 同一文件`，不传 `--publish-after`。事件文件必须不存在，发布后独占创建；若文件写入失败、运行标识或摘要不符，报告失败或保持未完成。不要复用旧运行的 UUID 或事件文件。网络接口仍只接受 `127.0.0.1`，任何隧道和测试网络都必须由操作者自行隔离并确认，不得连接生产。

每个分片必须在开始前成功输出 `ready`；若任意分片失败、超时、没有准备好或时钟不可信，操作者必须停止整个隔离测试。当前工具**不会自动取消其他分片**。发布事件到达较晚时，分片可根据先前记录的首次版本回执补算；跨主机时间按本机时钟换算并明确标记为未验证，版本再次变化时这一记录可能保守低估。各分片仍须监控漏发、资源、数据库和运行材料身份。

各进程正常结束后，使用 `python -m tools.load_merge 分片1.jsonl 分片2.jsonl ...` 检查区间重叠、版本事件、候选摘要、时间和计数，并合并心跳时延直方图。汇总的规模是**已配置规模**，不能单独证明实际存量；开始时间偏差不能证明主机时钟准确。合成策略回执不执行真实配置校准；全局时效、容量和发布验收始终显示未完成，须另核验时钟、全部主机和数据库指标及真实客户端回执。Linux 跨机执行、共享文件行为和 8 小时长稳尚未验证。


## 隔离 MySQL 集成测试账号

`server/tests` 的 MySQL 夹具只连接 `127.0.0.1`，默认端口 13306，可通过 `ENDPOINTAI_TEST_MYSQL_PORT` 修改；设置 `ENDPOINTAI_TEST_MYSQL_USER` 和 `ENDPOINTAI_TEST_MYSQL_PASSWORD` 可使用专用隔离数据库账号，未设置时保留旧的测试默认值。密码只通过受保护的进程环境提供，禁止放入命令历史、日志或报告。测试账号需有在隔离实例中创建、维护并删除随机 `eai_test_` 前缀测试库的权限；这些是 MySQL 权限，不要求 Linux 系统 root。测试会自动删除自己创建的库，不得指向生产实例、生产数据或生产隧道。

`server/tools/scale_inventory_probe.py` 也支持上述测试账号环境变量，默认仍为原有本机测试账号。该工具使用随机 `eai_scale_` 前缀建库、维护及删库，因此专用账号还须获准操作该前缀的测试库；仍须先确认整个实例、目录及连接链路与生产隔离。账号选择已做单元测试并用本机测试账号完成小规模实测；专用受限账号的完整权限路径尚未验证。

本次本机实例中无授权转授权限，已验证环境变量选择生效及无权限账号被拒绝；尚未验证按前缀授权的非 root 测试账号完整执行，目标环境需另行验证。


## 精简心跳负载

`--compact-v2` 只对新版 v2 合成设备启用独立精简心跳：建档时要求服务端明确宣告支持，之后无变化的心跳省略用户和代理清单。旧版 v1、旧版完整 v2 仍按原模式，未指定该参数时保持以前的轻量心跳，便于分别测试版本组合。工具将参数、精简请求成功数及错误数记入报告，评估器仅在确有精简请求且没有报告错误时标记该项被观察；分片汇总同时显示配置的精简在线数与请求计数，不将其视作容量或真实终端验收。

发压模式不会模拟客户端遇旧服务时的自动回退；若服务不支持，建档或请求会失败，以免误认为已覆盖新接口。混合服务版本、回退、资产变更及设备绑定行为需另用真实客户端验收。当前示例心跳的一名合成用户和一个合成代理，未加密 JSON 从 1756 字节降至 1333 字节；实际节省取决于数据和加密开销，不能外推为总带宽或容量承诺。

## 实时综合搜索的独立对照

`python -m tools.scale_inventory_probe --isolated-mysql --devices 150000 --online 100000 --assets-per-device 0 --samples 1 --policy-samples 0 --compare-correlated-search`
