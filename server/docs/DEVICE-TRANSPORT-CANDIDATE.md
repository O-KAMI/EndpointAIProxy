# 设备绑定传输封装：隔离候选

工作树另有默认关闭的[设备凭据两阶段更新](CREDENTIAL-ROTATION-CANDIDATE.md)，
需显式维护 schema 6，本机跨语言断点回归已通过，原生及 Linux 门禁仍未通过；
该增量不包含在此前 r75/0.2.19 包内。
下文“不是无中断轮换”描述旧设备封装能力本身，不能当作新增量已部署或验收的证明。

当前候选新增下文 V2 服务端独立密钥方案；本文原先的 Token 验证值派生方案记作 V1，仅供兼容早期 0.2.14 候选，不推荐新部署启用。两者默认均关闭。

这是默认关闭的候选能力，不能据此启用生产。服务端先部署候选并完成既有 schema 升级、回退、负载及安全验收；现有共享封装和旧 .NET/Go 客户端仍受支持。首次注册与首次心跳沿用共享封装，只有控制端确认 HTTPS、客户端使用固定服务器公钥的 HTTPS 并收到已认证的能力响应后，新 Go 客户端才改用设备绑定封装。V1 仅在进程内保留；0.2.16 V2 将绑定状态持久化。HTTP 客户端不会切换；当前生产 Windows 配置仍为 HTTP，因此不会自动获得此能力。

## 机制与局限

- 封装主密钥由设备 Token 的 SHA-256 验证值、固定域分隔符及规范化设备 UUID 经 HMAC-SHA256 派生，再使用现有方向分离 HKDF 和 AES-GCM。每个设备有独立封装密钥；请求绑定设备 UUID、Token 和允许的 v2 路径，并继续执行独立提交的防重放及设备认证。设备 ID 出现在封装密钥 ID 中，应视为敏感元数据；传输必须经 HTTPS。
- 此方案的传输密钥**不是独立于设备 Token 的凭据**。数据库中的 Token 哈希可派生封装密钥；若攻击者同时取得哈希和对应明文封装记录，可能解出 Token。必须保护数据库、TLS 终止点和备份，禁止记录封装正文。它不能抵御数据库泄漏，也不代替后续独立密钥、设备证明或完善的密钥生命周期设计。
- 为旧客户端及引导保留共享传输密钥；它泄漏后仍会影响旧路径。首次注册的安全仍依赖可信 HTTPS、证书固定与引导凭据。旧 HTTP 部署中的 Token 可能已暴露，必须先在隔离环境核验受控更新和恢复，不得假设切换封装就能消除既有泄漏风险。策略 HMAC 与共享密钥是另一风险，Ed25519 签名需另行迁移。
- Token 经现有管理员凭据恢复更换后，新的设备封装密钥随之改变，旧密钥立即不能用于新请求。这不是无中断双密钥轮换：客户端持有旧 Token 时无法自行取得新 Token，须通过既有受控恢复流程交付。当前进程一旦切换，不因失败自动回退共享封装；如果停用服务端能力或回滚，已切换进程会报错，必须事先准备经验证的分批恢复方案。进程重启后会在固定 HTTPS 上重新协商，不代表全生命周期强制设备封装。
- 每个设备封装先读取一次数据库验证值，业务认证目前还会再次核验；未知设备 ID 也可能触发一次读取。该路径增加数据库及入口负载，必须实施入口访问控制与限流并验证 10 万在线、恶意请求、重连和策略尖峰；不得因本地单元测试通过就启用。

## 隔离验证要点

在独立隔离环境中准备私有测试账号、测试数据库和与生产无关的证书；用户提供并独立校验服务端公钥固定值。服务端候选可设置 `SF_CONTROL_DEVICE_TRANSPORT=true`。生产配置校验要求服务监听在回环地址，并启用 `SF_CONTROL_TRUST_LOOPBACK_PROXY=true`；TLS 代理应只对可信入口转发并正确设置 HTTPS 标记。切勿在现网直接尝试、修改 TLS、清库或批量重新注册。

覆盖首次和既有客户端、旧客户端并存、固定值错误、非 HTTPS、跨设备绑定、令牌变更/吊销、响应丢失、重启与服务回退、防重放、代理重启，以及分批发布和安全恢复。每一步记录候选包摘要、配置版本、实际回执和数据库负载。签名密钥、Token、完整封装和真实请求体不得进入报告。仅固定证书和合成数据的本机互通不足以证明生产安全、可用性或容量。


## V2：独立服务端密钥与重叠轮换（候选）

V2 由服务端持有独立的 32 字节随机主密钥，结合规范设备 UUID 和该设备 Token 验证值通过 HMAC-SHA256 派生设备封装密钥；数据库验证值单独泄露不足以计算 V2 封装密钥。密钥由服务器在设备已认证、客户端明确声明 V2 支持、外层为 HTTPS 的心跳响应中交付；新客户端只在固定服务器公钥的 HTTPS 上接受并在内存使用。密钥不写入客户端状态数据库，响应使用 `Cache-Control: no-store`；设备 ID 与密钥代号仍是敏感元数据。

这是**集中主密钥派生**，不是设备各自独立生成的私钥或硬件设备证明。服务端主密钥与数据库验证值同时泄露会影响整批设备；已泄露的原 Token、共享引导密钥或 TLS 终止点也有各自风险。必须分别保护主密钥、数据库和终止点；不将主密钥、派生密钥、Token、完整封装或请求体写入日志和验收材料。旧客户端未声明 V2 时服务端不发送派生密钥；旧版的 HTTP 共享封装仍受原有风险约束。

隔离候选设置为 `SF_CONTROL_DEVICE_TRANSPORT_V2=true`，并以受保护方式分别设置 `SF_CONTROL_DEVICE_KEY_ID` 和 `SF_CONTROL_DEVICE_KEY_SECRET`。代号为 1–10 位正整数字符，密钥为独立随机 32 字节的 Base64。还可设置 `SF_CONTROL_DEVICE_PREVIOUS_KEY_ID` 和 `SF_CONTROL_DEVICE_PREVIOUS_KEY_SECRET`，这两个字段表示**另一把允许解密的重叠密钥**，可以预置未来代号，不必小于当前代号。与共享封装、策略签名、本地管理会话或另一代密钥重复的密钥被拒绝；生产配置仍要求回环监听和受信任的 TLS 代理。不得将密钥放在安装包、源码、聊天或命令输出中。

旋转示例：先在**所有**服务工作进程上配置当前代号 1 和重叠代号 2，确认所有进程均能接受两代；再分批将当前代号改为 2、重叠代号改为 1。客户端使用旧代号请求时，服务端以旧代号加密响应并在已认证响应中提供当前代号；客户端在当前进程只接受更高代号，同代不同密钥报错，不会因失败自动降级。混合配置期间，尚提供旧代号的服务器也必须已预置新代号。离线或未回连的客户端可能仍持旧密钥，不能依据时间盲目删除重叠代号；覆盖率、回退、失联和异常必须事先核验。

0.2.15 V2 重启后会使用共享引导重新协商；0.2.16 V2 将服务地址、固定公钥、设备密钥、代号和令牌摘要写入受平台保护的状态库，并在后续启动先恢复。恢复失败或身份改变时控制连接停止，离线有效策略仍可使用；不能防止有权访问本地状态者删除或回滚整个数据库，迁移、恢复和原生平台行为仍待隔离验收。设备 Token 经管理员恢复更换后，派生密钥随之更换，但旧进程无法自动取得新 Token，需受控恢复；这不是设备凭据的无中断双密钥轮换。V2 仍为每次设备封装额外读取数据库，未经 10 万在线、滥用、代理和 Linux 多进程验证，不能启用生产。旧 .NET 客户端当前不支持 HTTPS 与原 AES 封装组合，真实测试失败；必须保留兼容的旧 HTTP 路径并规划退役，不能直接将其切往新入口。


## 首次注册响应丢失

候选控制端接受新 Go 客户端生成并持久化的 32 字节随机初始设备凭据。首次注册成功但响应丢失时，客户端可重启后使用相同凭据重试；已注册设备仍需相同凭据证明，吊销状态不会因重试恢复。该能力不为旧客户端提供首次注册自动恢复，也不能迁移已有设备凭据；旧控制端忽略新增字段，响应丢失仍需受控恢复。初始设备凭据与注册响应同样属于敏感数据，不得记录或上传。此功能尚需 Linux、原生终端、并发负载和故障注入验收。
