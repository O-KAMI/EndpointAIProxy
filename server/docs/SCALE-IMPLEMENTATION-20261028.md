# 规模优化工作树记录 · 2026-10-28

范围为 Go Win/Mac 客户端和 Python/MySQL 控制端。此记录是本地源码与隔离验证，
不是安装包、生产部署或 15 万端容量验收。已有工作树改动保留；未连接或修改生产环境。

服务器操作权限约束：使用者没有服务器 root 权限。系统级 systemd、系统 Nginx、
443 监听和系统日志轮转均不能假定可自行配置；需要现有受管入口或服务器管理员
协助。普通账号的 user systemd 是否可用、退出登录及重启后是否持续运行均待核验，
不可把 user service 模板视作已解决开机自启或高可用。

2026-10-28 用户调整推广验收口径：控制端长稳由 72 小时改为 **8 小时**；
Windows 推广包**不进行代码签名**。Windows 仍需对最终包进行摘要绑定及原生、
安装、回滚和 IOA 验收；Mac 的正式签名、公证和原生验收要求不受此调整影响。
Windows 源码新候选使用 0.2.5，避免与已冻结的 0.2.4 安装包复用安装版本。

## 已实现

- 控制同步：启动随机延迟 0–30 秒；正常心跳和完整策略核对带 10% 抖动；
  失败重试使用有界随机指数退避。心跳返回的有效策略版本变化时触发策略拉取，
  另以至少 10 分钟间隔做完整核对。阶段失败不阻塞其他阶段。
- 新客户端在收到服务端能力确认后使用无状态策略版本读取；旧客户端继续旧路径。
  无状态读取保留现有已签发版本及覆盖，首次 schema 2 可使用同一版本升级；
  全局变更版本仍在发布事务中超过已签发水位。已有覆盖状态的旧客户端在全局更新后
  复用新全局版本，在共享策略锁下刷新各自覆盖；首次升级 schema 等需分配新版本的
  情况仍争用全局锁。全局发布和单终端覆盖仍执行 MAX 查询。
- `manage.py ensure-scale-indexes --env <环境> --service-stopped` 增加策略版本索引，
  并重建工号和异常检索派生表；不改变已有版本水位或 schema 校验和。操作
  会执行 MySQL DDL，须先备份并在停止全部应用后执行。之后在所有服务中设置
  `SF_CONTROL_EMPLOYEE_INDEX=true` 才使用并维护两张派生表。它降低 MAX 查找成本，
  但不会消除旧客户端的全部版本锁。回退到旧服务前必须关闭该配置；旧服务会使
  派生表过期，再次启用前需停机重建。派生表不进入原备份清单，开启该配置时
  恢复流程从备份心跳、资产和活动记录重建；旧 schema 迁移应先关闭该配置，迁移后重建派生表
  再启用。Linux 备份恢复实操仍待验收。
- 服务端每进程最多复用 8 个事务连接，等待最多 5 秒；坏连接不复用，
  各事务仍单独提交或回滚。鉴权时间最多约每 5 分钟更新一次。
  防重放仍先于业务提交，过期清理由正式 app.py Gunicorn 入口的后台任务执行；
  其他 WSGI 启动方式必须自行接入维护任务，不可直接用于生产。连接池耗尽时
  加密通道返回经认证的 503/Retry-After，客户端遵守有限重试等待。
- 服务端确认能力后，Go 客户端只在完整资产快照被服务端确认后使用轻量心跳，
  轻量请求保留运行状态和活动信息，服务端不会把省略的资产当成删除；约每五分钟
  （带抖动）重新扫描，摘要变化才发送完整资产，约每小时完整校准。摘要不包含
  观察时间；已检测的配置变更或代理操作触发下一次扫描。客户端重启和旧服务均先
  使用完整上报；无法通过现有配置监视器发现的外部变更在下一次扫描发现。
  轻量心跳使用独立路径；服务端回退到不支持该路径的旧版本时，新客户端收到
  经认证的 404 后立即重发完整心跳，避免旧服务把省略的资产误认为删除。
  本地配置文件状态检查间隔由 500 毫秒调整为 5 秒；显式策略校准请求仍即时触发。
- 成功控制请求按进程/分钟聚合并按认证信封 ID 约千分之一抽样；失败仍逐条记录。
  聚合包含 50、100、200、500、1000 ms 累计延迟桶，可在日志侧估算区间分位数；
  聚合在后续请求跨分钟时输出，进程突然退出可能丢失当前未输出的计数。尚未
  接入统一指标采集和告警，失败请求也不在成功请求延迟桶内。
- 正式 Gunicorn 入口的每个 worker 每分钟记录连接池占用、累计申请、耗尽、
  累计等待和最大等待时间；按 PID、角色分开，进程重启会重置累计值。可按进程
  计算耗尽计数增量；出现新增耗尽时另写 `POOL_EXHAUSTION_ALERT` 警告日志。
  尚未接入统一采集和通知，也不能由该日志推导数据库锁等待。
- 首次注册正常；重复注册需要现有设备 Token，已吊销设备不会被普通注册恢复。
  新客户端先发送旧格式，收到已认证的 409 后才携带现有设备 Token 重试，以兼容旧服务。
  增加受控恢复：仅 HTTPS 本地 admin 可以凭设备 ID、精确主机名和原因签发替代
  Token，立即废止旧 Token、恢复吊销状态并事务审计。终端服务停止后，管理员把
  一次性 JSON 经受控渠道传给 `--maintenance=recover-credential` 的标准输入；
  维护程序核对本机已有设备 ID、向已配置控制服务验签并验证凭据后才保护写入，
  不重建身份或清库。恢复材料关闭后不可再次查看；网络中断时结果可能未知，
  应核验并重新发起。旧 .NET 客户端自行重复注册仍不能证明旧 Token；Go 维护
  程序与旧版现场状态的具体恢复仍需独立 Windows 验收，不能据源码宣称完成迁移。
- 全局策略更新与版本摘要在同一事务写入管理审计。本地账号模式的操作人来自
  服务端认证，旧共享 Token 模式仍信任请求头，不能视为实名审计。
- 默认资产列表及仅含工号、主机名或设备 ID 搜索的列表，在 MySQL 一致性快照中
  分页后再读取当前页；启用工号派生表后搜索扫描归一化工号，避免逐行解析心跳。
  带 Agent、供应方、异常或白名单等复杂筛选的列表与汇总仍读取全量数据。
- 旧设备列表接口的主机名/设备 ID 搜索和分页也改为数据库执行；复杂资产筛选
  和统计仍需完整读模型。旧 dashboard 的在线状态与版本统计改为 SQL 聚合，
  不再加载全部设备的资产。
- 已过期但仍为 executing 的远程命令可由管理员填写原因、核验终端后标记结果未知，
  在事务中审计并解除活动槽；迟到的执行中回执不会重新占槽，迟到的终态回执仍记录。
  操作者身份在旧共享 Token 模式下仍受请求头限制。
- 可选本地账号模式支持 admin、operator、viewer 三种角色及 HTTPS 会话；账号
  禁用或密码变更会使原会话失效。旧 Token 模式仍为默认，启用前必须配置专用
  HTTPS 入口、私有账号文件及独立会话密钥，并在目标 Linux 环境验证部署与回滚。
- 统计和详情统一识别 Go 的 completed 与 .NET 的 SUCCESS；没有成功校准证据
  或有校准错误时不计为已应用。Go 新策略应用后清除上一版校准状态。
- Go 本机代理共享 64 个并发转发槽，上游首个响应头最长等待 5 分钟；
  槽满返回 503 和 Retry-After。捕获创建和写入中检查 512 MiB 磁盘余量，低水位
  停止捕获并标记审计降级，业务请求继续；这不是总容量硬配额，多并发及外部写盘
  仍可能越过水位。上游响应流连续 10 分钟无数据时取消并记录超时；捕获总容量
  硬配额仍待设计验证。
- 新增 SQLite 表 pending_control_events，保留最多 1,000 条事件，重启后恢复，
  服务端确认接收或去重后删除；溢出和本地持久化失败记录脱敏错误码。
  磁盘写入失败时事件仅在内存排队，重启持久性无法保证。
- 新增 deploy/endpointai-appdeploy.service 模板，现有 logrotate 模板保留。
  它未安装；现有 0.1.25 升级脚本会拒绝 systemd 托管，切换前必须准备并验证
  与托管模式相匹配的升级和回滚流程。
- 增加可选分离运行模式：客户端接口和管理接口分别由独立进程服务，仅监听本机；
  客户端进程每 worker 最多 8 个数据库连接，管理进程最多 2 个，Nginx 模板分别
  转发。原单进程入口仍兼容。模板未部署，须在 Linux 验证并发隔离和实际升级回滚。
- 新增两个 `*.user.service.example` 普通用户服务模板，不需要在单元文件指定
  root、User 或 Group；它们仅是备选模板，需先确认目标服务器的用户服务管理器、
  目录权限和登录会话结束后的生命周期。现有升级脚本与托管服务仍不兼容。

## 策略及命令公钥验签候选（尚未部署）

- 服务端可选配置 `SF_CONTROL_POLICY_ED25519_SEED`（Base64 编码的 32 字节私钥种子）。
  `tools/create_policy_signing_key.py --directory <新建的私有目录>` 在普通 Linux 用户下
  生成受限文件，私钥和公钥写入不同文件，不向终端输出私钥。目录不能已存在或包含
  符号链接；保管好种子并备份。工具的 Linux 权限及实际私钥配置尚未现场验证。
- 新客户端私有配置可用 `policyPublicKey` 替代 `policyHmacKey`，公钥为 Base64 编码的
  32 字节 Ed25519 原始公钥。两种字段必须且只能选一种；不能通过自动降级回到 HMAC。
  Windows 和 Go Mac 构建输入均支持该格式。旧客户端继续沿用 HMAC，服务端必须保留旧
  HMAC，直到旧客户端全部退出。禁止将私钥种子放进客户端包、仓库或报告。
- 必须先在隔离服务验证服务端私钥与公钥匹配、持久备份、旧客户端兼容，再构建并试点
  公钥客户端；服务端未配置对应私钥或仍是旧版本时，新模式会拒绝策略和命令，不能
  将这种失败视为可自动回退。切换后的旧客户端回退需要事先保留受保护的旧版凭据和
  安装恢复材料。现有公钥格式只支持单个公钥，在线轮换和密钥撤销流程尚未实现。
- 新签名策略的精确原始字节会保存在既有离线缓存中，启动时重新验签；首次切换时为
  保留断网可用性，已有 HMAC 缓存仍按原先的受保护本地缓存语义使用，直到收到相同或
  更新版本的公钥签名策略。这不是对历史缓存重新验签，旧缓存过渡与缓存回退风险仍需
  在受控终端验收，不能宣称所有离线缓存都已达到新签名安全级别。
- 加密传输密钥和首次注册凭据仍是共享配置；公钥策略签名不等于设备级传输身份，也
  不解决共享传输密钥泄露或观察到的设备 Token 暴露。该部分仍为推广安全阻断项。
- Go 单元测试和 vet、Python 隔离服务签名兼容及跨语言合成签名向量已通过；Mac Intel／
  ARM64 已交叉编译。Windows/Mac 真实安装、Linux 真实服务配置、密钥切换和故障恢复
  尚未完成。已重新构建 0.2.5-r3 未签名 Windows 候选并绑定摘要，但其配置仍使用 HMAC；
  独立终端验收须绑定 r3 摘要，旧候选的验收证据不能继承。

## Mac 公证与外部凭据

旧 Mac 构建流程把客户端凭据嵌入 PKG；Apple 公证会上传整个包，禁止将含真实凭据的
旧包提交公证。新增 Go 外部凭据模式：构建不含凭据的 PKG，公证脚本检查该模式并拒绝

受保护目录快照该文件并用于 pre/postinstall，以免两阶段读取不同内容。
这是源码级实现，Mac 的脚本模拟、实际签名/公证和两架构原生安装仍未验证；不据此
放行。具体步骤及安全边界见 [Mac 交接说明](../../docs/MACOS-GO-025-HANDOFF.md)。

## 本地管理账号启用步骤（尚未部署）

- 使用 `tools/create_local_admin_accounts.py --file <私有绝对路径> --account <工号>:admin`
  创建新文件；可重复 `--account` 创建 operator 和 viewer。密码交互输入且不写入日志；
  文件必须由运行账户持有且仅该账户可读写，目录也须限制访问。工具不会覆盖文件。
  调整账号或密码时在受保护目录创建新文件并原子替换；保留至少一个启用的 admin。
- 在受保护的 launch-env.json 中配置 `SF_CONTROL_ADMIN_AUTH_MODE=local`、
  `SF_CONTROL_ADMIN_ACCOUNTS_PATH`、`SF_CONTROL_ADMIN_SESSION_KEY`（独立随机至少
  32 字节的 Base64），以及 `SF_CONTROL_HTTP_HOST=127.0.0.1`、
  `SF_CONTROL_TRUST_LOOPBACK_PROXY=true`。会话密钥
  改变会使所有会话失效；不要将密钥、账号文件或真实密码提交至 Git 或日志。
- `deploy/nginx-local-admin.conf.example` 和两个分离服务是未安装的模板：8080
  转发至客户端进程的 18080 端口，443 管理入口转发至管理进程的 18081 端口；
  按模板启用两个进程，不要同时启用单进程服务。替换域名和证书路径，限制管理入口的网络访问，并在
  Linux 检查配置、证书、转发头、速率限制和客户端兼容后受控切换。应用的 loopback
  信任只防止外部直连伪造转发头，必须保证本机其他进程也可信。
  该 Nginx 模板涉及系统入口与证书权限；没有 root 权限时只能在已有受管入口
  支持相同路由和可信转发头的前提下使用，或由服务器管理员实施。不要自行假定
  443 可绑定，也不能用明文管理入口替代本地账号模式要求的 HTTPS。
- viewer 只读；operator 可读和操作远程命令；admin 可执行全部管理操作。
  登录尝试在应用每个 worker 内按来源和账号组合限制 5 分钟内 10 次，并按来源
  限制 100 次；模板另在 Nginx 限流，均非跨服务器共享。大量用户共用出口时，
  来源总限额仍可能同时影响他们；需要按受管入口的真实网络情况验证与调整。
  需记录账户维护与访问审计并保护账户文件；当前没有管理 UI 自助维护账号、
  主动注销服务端会话或独立的失败登录审计。TLS 未验收前不要启用生产。
- 会话绑定密码哈希和角色；密码或角色不同、账号禁用时旧会话被拒绝。若将账号
  文件恢复到完全相同的旧密码哈希和角色，尚未到期的旧会话可能重新有效；需要
  永久撤销时轮换所有进程使用的会话密钥，或同时重新生成受影响账号的密码哈希。

## 终端凭据恢复（仅供隔离验收，未部署）

1. 先确认终端身份、完整主机名与控制服务；停止终端服务并确认监听与实例锁释放。
   原始数据库与配置备份保留。仅本地 admin 登录控制台，填写精确主机名和不含
   凭据的原因后签发恢复材料；此时旧 Token 立即失效，操作记录写入审计。
2. 将仅显示一次的 JSON 经受控渠道送到目标终端管理员，放在仅管理员可读的临时
   文件中，关闭对话框并清理剪贴板。切勿放在命令行参数、普通日志或公开目录。
   客户端维护程序从标准输入读 JSON，例如在提升权限的 PowerShell 中使用
   `Get-Content -LiteralPath $PrivateRecoveryFile -Raw -Encoding UTF8 | & $ClientExe --maintenance=recover-credential`。
   `$PrivateRecoveryFile` 和 `$ClientExe` 必须由操作人员指向目标机器上的实际路径。
3. 工具确认本机已有设备 ID 与材料匹配，并通过现有加密控制通道验证替代 Token
   和策略签名后才覆盖受保护凭据；失败保留原本地凭据。确认成功后启动服务、
   检查策略及心跳，按组织的受控流程删除临时材料。服务端响应丢失可能已经轮换
   Token，应核验设备状态并重新发起，不能假定旧 Token 仍有效。

## 管理统计快照读模型（候选实现，默认关闭）

新增独立刷新任务：在一次一致性快照中按操作系统、在线状态和旧客户端标记生成
互不重叠的汇总分区；管理 API 从本机快照合并所需范围，支持原有系统子串筛选。
汇总快照不含设备明细；可选的筛选索引快照包含设备明细，二者均须作为内部敏感数据保护。
快照文件使用私有临时文件并原子替换，失败保留旧快照；MySQL 命名锁阻止对同一
数据库的并发刷新。最多 4096 分区、32 MiB 文件；超过限制会拒绝刷新并保留旧值。

启用步骤，须先在隔离 Linux 依次验证，不是生产部署指令：

1. 用与管理服务相同的普通账号和受保护配置，执行部署目录下的
   `.venv/bin/python start.py --refresh-analytics-cache`。该入口读取现有私有
   `launch-env.json`，无需在命令行或日志中填写数据库密码。刷新进程与管理进程须
   使用同一个 `SF_CONTROL_DATA_ROOT`，目录应只允许服务账号及必要管理员访问。
2. 验证生成的 `analytics-cache.json` 仅服务账号可读写，配置管理进程的私有环境
   `SF_CONTROL_ANALYTICS_CACHE=true` 后重启受控的管理进程。未启用时保留同步统计。
   找不到、损坏或数据库身份不符的快照返回 503，不会退回并发全量扫描。
3. 在目标机器允许的普通用户调度器中周期执行同一刷新命令并监控退出码、时长、
   最近成功时间、磁盘与 MySQL 长事务；是否支持开机启动、退出登录后运行及重启
   恢复必须现场验证。暂以每 2 分钟触发作为隔离试验起点，若上一次尚未结束，
   命名锁使后续任务失败退出，不能忽略或无限叠加。监控快照年龄，不要按触发间隔
   假定数据新鲜。恢复数据库、切换数据源或更换控制端后先重建快照再开放管理入口。
4. 页面标明快照时间、超过 5 分钟警告；未启用筛选索引时图表明细实时读取，数量可能与快照不同。
   快照策略版本及已应用数量均是生成时的状态，不能作为实时发布成功回执。

本机隔离 MySQL 合成 15 万设备、10 万在线、每台一个资产，独立运行一次刷新
为 89.386 秒，生成 2548 字节，三次读取均为 0.008 秒；不含 HTTP、真实心跳、
管理并发、真实目标分布或 Linux 环境。由于扫描仍会产生长事务和数据库负载，必须
先完成混合负载和 8 小时长稳验证；未证明在现有服务器可满足 10 万在线。复杂设备
筛选路径仍可能全量扫描，且多机器部署不能仅共享数据库锁而使用彼此独立的本地
快照；当前方案只面向同一服务器的管理进程和刷新任务。

本轮隔离 MySQL 与控制台专项 33 项通过；额外 502 台跨数据库分页与原汇总对照通过。
控制端广泛回归 178 通过、15 跳过、1 项 Windows 不支持的 Gunicorn 测试排除；
Unix 专属备份、维护和升级测试未包含，仍需在隔离 Linux 完成。


## 复杂筛选的内存与并发保护（2026-10-29）

复杂设备筛选不再一次载入所有设备及资产：在单个一致性快照内按心跳时间和设备 ID

## 复杂筛选的索引快照（候选实现，默认关闭）

新增可选 SQLite 索引文件，刷新汇总时在同一 MySQL 一致性快照中生成设备投影和筛选
索引。范围、系统、Agent、供应方、异常、白名单、关键词及其组合查询使用该文件；
基本列表默认仍走实时 MySQL 查询；管理员可明确选择快照列表。筛选界面显示生成时间和过期提示，设备详情及控制操作
继续读取实时服务端状态。索引支持的筛选规则与原实现做了多范围、多条件和分页对照。

仅在隔离 Linux 环境测试时，可在管理服务与刷新任务的私有配置中设置
`SF_CONTROL_ANALYTICS_DETAIL_CACHE=true`，并先执行既有 `start.py --refresh-analytics-cache`。
缺失、损坏、数据库身份不符的索引返回 503，不自动回退到昂贵的同步扫描。该开关独立

请求目标及资产投影，必须限制到服务账号和必要管理员；备份、日志、诊断上传不能
无意带出。启用前须核实数据根目录权限、可用空间和磁盘监控。索引文件上限 2 GiB；
构建会额外占用临时文件空间，异常退出可能留下受保护的临时文件，需由运维核验清理。

索引和汇总从同一快照生成，但两个文件分别原子替换；中途失败可能暂时分别显示不同

启用后须确保普通账号刷新任务持续运行，依据实际耗时确定周期并监控退出码、快照年龄、
数据库长事务、空间和心跳延迟。一次刷新若超过调度间隔，命名锁会让重叠任务失败退出。

本机隔离 MySQL 实验：15 万存量、10 万在线、每台一个资产；一次同时生成汇总和索引
耗时 153.310 秒，索引 343,736,320 字节，供应方筛选三次读取 1.151、1.087、1.224 秒。

# 控制台退出当前页面

控制台“退出当前页面”会清除本页持有的凭据和会话存储并重新加载页面；不会
注销其他页面，也不会即时撤销已签发的服务端会话。现有本地账号会话最长有效
8 小时，账号禁用、密码或角色变更会使旧会话失效；单会话即时撤销尚未实现。
旧版共享管理 Token 的服务端失效仍需轮换 Token。

# 过期执行中命令的控制端投递保护

候选控制端不再向客户端投递已过期且仍为 executing 的命令，保持该命令活动槽
及状态，直到管理员核验并标记结果未知或收到迟到终态回执。这样也能减少旧客户端
在重复领取时重新执行的风险；已经投递出去的命令不受此保护。正常过期前的领取和
迟到终态回执仍保留。此改动尚未部署，不能视作现网已受保护。

# 策略汇总显示口径

策略汇总覆盖全部终端，包括离线终端，结果基于最后一次上报；“未确认校准成功”
包括未同步、校准失败、不支持和没有足够结果等情况，不等同于全部正在等待同步。
批次的校准成功数也基于最后上报，不是对离线终端当前状态的确认。

# 已投递命令的过期处理

执行中回执可能丢失，因此候选控制端对已投递但仍无终态的过期命令保留活动槽，
不自动标为过期或再次投递；管理员核验后可标记结果未知，或等待迟到的终态回执。
从未投递的 pending 命令仍可自动过期并释放活动槽。控制台在已投递或执行中命令
跨过有效期时显示人工核验入口，即使终端离线没有新心跳也会在下一次详情刷新显示。
这一较保守的行为可能增加人工处理量；已投递的请求无法由服务端撤回，现网未部署。

# 命令批次目标筛选

控制台命令批次接入服务端状态筛选，可定位下发失败、执行失败、结果未知等目标，
使用后端分页并忽略过期响应；筛选结果收缩到当前页之外时回到第一页。批次计数
和目标状态使用可读名称。筛选和查询的 15 万设备真实容量仍需隔离压测。

# 批次目标批量写入

命令批次创建、策略批次创建及追加目标的插入语句全部使用参数占位符，使 PyMySQL
能够将每组目标合并为多行插入；事务边界、快照、速率和审计语义不变。隔离 MySQL
回归覆盖批次状态、并发及审计失败后的整体回滚。

本机 Windows 的隔离 MySQL、15 万合成目标、单次对比、无 HTTP 和并发心跳下，

7.524 秒，目标验证分别为 4.305 和 6.452 秒。样本仅反映该机器本次实验，不是

另外，15 万设备、10 万在线、无资产的合成单次复测中，在线列表首页 2.577 秒、
末页 3.208 秒，工号检索在派生表关闭和开启时分别为 9.281 与 3.237 秒；均

## 工号精确搜索（候选）

控制台新增“工号精确搜索”，按回车或刷新执行；原综合搜索的主机名、设备 ID 与工号子串语义保持不变。精确搜索对已识别的完整工号做大小写不敏感匹配，不匹配主机名或设备 ID；可以与现有筛选组合。开启详情快照时使用工号索引并显示快照时间和陈旧提示；未开启时使用有并发限制的实时分批扫描，大规模环境不能假定该路径满足延迟门槛。

详情快照格式从 2 升为 3。启用快照的候选服务需先在隔离环境执行 `start.py --refresh-analytics-cache` 更新快照；旧格式或刷新失败时复杂筛选及工号精确搜索返回 503，不回退为全量扫描。回退旧服务也需用旧版本刷新快照。索引仍含工号，遵循上述私有数据保护要求。

本机 Windows SQLite 单次合成试验建立 15 万设备及各一个工号，不含 HTTP、刷新或并发写入；命中工号 0.0411、0.0020 秒，未命中 0.0018 秒，查询计划使用工号索引。非完整生产数据、非 p95，也不能证明 2 秒容量门槛。


## 已有凭据的安全重注册（候选）

Go 0.2.13 在重注册时先尝试不带旧 Token；收到已认证的 409 后，携带原 Token 和 `preserveDeviceToken=true`。支持该字段的候选控制端在原 Token 有效且未吊销时返回原 Token 和原注册时间，不更新凭据；因此丢失响应后可重复请求。无原 Token、错误 Token 或已吊销凭据仍拒绝。旧客户端不发送该字段，继续保留既有“验证旧 Token 后换发”的行为。控制端必须先升级并在隔离环境核验：旧控制端会忽略新字段并仍然换发，不能声称旧服务具备响应丢失保护。

首次注册结果丢失时客户端尚无有效凭据，仍需管理恢复，不能通过清库或自动覆盖解决。该能力只是减少已持有凭据重注册的丢失窗口，不提供自动凭据轮换，也不解决共享传输密钥泄漏；设备级可轮换传输身份和入口 TLS 仍需实施及验收。候选服务的并发重复注册使用直接独占行锁，避免重复插入后锁升级造成死锁；仍需在隔离 Linux 多进程、数据库故障和真实客户端上验收。


## 资产列表快照选择（候选）

资产管理提供“自动选择数据源”和“使用快照列表”。自动模式保留现有行为：基本筛选使用实时 MySQL，复杂筛选在启用详情快照时可能使用快照，界面显示相应时间。明确选择快照时，包括基本列表在内均使用已有详情快照；设备在线状态、筛选和数量反映快照生成时刻，进入详情及控制操作继续读取实时信息。未启用、缺失、损坏或身份不符的快照返回 503，不静默回退为实时大查询；选择自动模式可恢复原路径。

启用前仍须在隔离环境准备 `SF_CONTROL_ANALYTICS_DETAIL_CACHE=true`、私有数据目录和定时刷新；快照可能超过 5 分钟，界面会提示陈旧。综合子串搜索可在支持 FTS5 trigram 的 SQLite 中利用索引；短于三个字符、包含 NUL 的关键词以及未建立索引的旧快照仍扫描，宽泛关键词可能更慢，不能假定满足延迟门槛。

本机 SQLite 单项实验使用 15 万合成设备、10 万在线、最小化展示字段，在线快照列表每页 25 条：首页五次为 0.1033、0.0440、0.0453、0.0501、0.0550 秒；第 99,976 条起五次为 0.0957、0.1071、0.0852、0.0818、0.0857 秒。不含快照生成、HTTP、真实资产体积及并发，不是 p95 或推广容量证明。


## 快照综合子串索引（候选）

生成详情快照时，如果当前 SQLite 支持 FTS5 的 trigram tokenizer，会在同一原子替换的文件中建立不保存原文的三字符索引。匹配前使用与原查询一致的小写归一化，候选结果仍逐字段验证，避免跨主机名、设备 ID 和工号边界产生误匹配。少于三个字符或含 NUL 的关键词走原扫描；旧格式 3 快照无索引时也走原扫描。旧版控制端可读取包含额外索引的新快照；升级和回退仍须遵守既有快照代际及数据目录权限要求。

如果 SQLite 明确报告缺少 FTS5 或 trigram，刷新保留原扫描路径；其他索引或磁盘错误会让刷新失败并保留旧快照。索引内容包含可推导出搜索文本的片段，仍是敏感资产数据。新增索引会消耗构建时间、内存和磁盘；两份文件原子替换期间仍需容纳旧文件与临时新文件。启用前应在隔离 Linux 核验 SQLite 能力、重建用时、2 GiB 文件限制、磁盘余量、刷新重叠与心跳延迟。

本机 Windows 的单次对照使用 15 万条最小合成设备投影、10 万在线，不含 MySQL 刷新、HTTP 和并发。索引快照构建约 16.005 秒、191,762,432 字节；未建索引约 15.837 秒、163,393,536 字节，两轮可能受到其他测试影响。选择性工号搜索（命中 1 台）索引三次 0.273、0.158、0.207 秒，扫描三次 1.377、0.925、1.006 秒；命中全部 10 万在线设备的宽泛词索引三次 1.434、0.840、0.672 秒，扫描三次 0.399、0.515、0.515 秒。样本不是 p95，不能证明真实数据和混合负载达到推广门槛。

## 精简用户和代理心跳候选（2026-11-01）

新 Go 客户端仅在收到服务端能力后使用独立 `/api/v2/heartbeat/light-compact` 路径，省略未变化的用户和代理；服务端在锁定的已确认基线上保留它们。旧服务对新路径的业务 404、旧设备绑定入口外层 400 会触发完整心跳重试，重试继续使用原设备传输身份；其他错误仍走原退避。完整上报、资产变化和低频完整校准保留。新路径受同样设备绑定、认证、防重放约束，未确认 v2 基线时拒绝，字段与路径不匹配时拒绝。

## 高速命令批次候选（2026-11-02）
