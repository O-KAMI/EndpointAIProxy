# 控制台与终端分析

控制台默认进入数据分析，另有策略管理（白名单、连接网关）和资产管理。
数据分析仅使用现有心跳、配置资产和最后请求结果，不采集请求正文，不统计请求量。

## 统计口径

- 默认在线终端；在线阈值沿用心跳间隔的两倍加 30 秒，陈旧阈值为五倍加 30 秒。
- Agent 覆盖按运行实例所在终端去重。多类 Agent 覆盖率可以超过 100%；实例构成按终端与实例标识去重。CC Switch 单独统计，疑似 Agent 不参与。
- 服务商按原始目标域名识别；已观测口径要求关联真实请求记录，配置口径只使用当前配置。未知域名单独显示，不推断中转服务背后的厂商。
- 最近异常指最后观测的代理请求结果失败，包含仍上报的未启用配置；曾异常仅使用本次服务运行的失败累计。重启后保留的旧结果不代表本次运行发生过失败。
- 白名单命中仅使用当前配置、已上报绕过标记和绕过路由状态，按标准化 Base URL 精确分组。同一终端跨多条规则的总数再次去重。终端尚未应用新策略时，旧的绕过地址仍显示为其已上报状态。
- 已观测服务商依据现存请求活动与配置资产关联。配置切换前的历史目标无法追溯；白名单直连请求无法通过本地代理观测。

## 管理接口

两个接口沿用现有管理员 Bearer 鉴权，不修改客户端协议或数据库结构。

| 接口 | 用途 |
|---|---|
| `GET /admin/v1/analytics` | 汇总、分布、策略应用数量和数据新鲜度 |
| `GET /admin/v1/analytics/devices` | 复用相同口径的终端筛选、请求结果和分页 |

公共参数为 `scope`（默认 `online`，另支持 `all`、`stale`、`offline`、`legacyClient`）、`os` 和 `providerMode`（默认 `observed`，另支持 `configured`）。
下钻支持 `kind`、`key`、`search`、`agent`、`provider`、`anomaly`（`latest`、`ever`、`none`）、`allowlist`、`skip` 和 `take`。
`take` 默认为 50，范围限制在 1–500；返回总终端数以及当前分页。图表和下钻共用服务端筛选与去重逻辑。

页面每 60 秒刷新，在不可见页面暂停轮询；详情沿用原有 15 秒刷新。
加载失败保留旧结果并提示陈旧；通过图表进入资产列表时保留分析条件，可单独清除。
策略保存使用已有乐观版本检查，冲突时保留编辑草稿。

## 验证

新增 `AnalyticsServiceTests`，并扩展 `ControlStoreTests` 验证数据库快照。
覆盖运行状态去重、心跳边界、服务商域名伪装、配置与请求区别、错误恢复、白名单标准化、旧客户端及分页。
本地浏览器联动验证使用临时数据库和 30 个测试终端，覆盖管理员鉴权、三个页面、下钻分页、详情返回、资产筛选、策略冲突与保存、390 像素窄屏。

服务商映射参考官方地址，例如 [OpenAI](https://platform.openai.com/docs/api-reference/models)、[火山方舟](https://www.volcengine.com/docs/82379/1795150) 和 [Kimi](https://platform.kimi.com/docs/api/chat)。
