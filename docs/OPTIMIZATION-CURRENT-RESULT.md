## 已实现的候选能力

- 客户端：启动错峰、失败退避、按版本拉取策略、轻量心跳和资产变化同步；
  保留离线缓存。事件持久队列、队列恢复、转发并发和超时、磁盘保护及新策略
  校准后的错峰回执已实现。完整队列仍可能溢出，必须监控。
- 0.2.19 修复事件队列溢出日志的丢弃数量字段此前被脱敏过滤的问题；隔离测试先复现缺失，修改后客户端相关测试及构建时 Go 全量测试、vet 通过。该字段记录的是此次持久队列操作的丢弃数，不等于服务端已经接收告警，日志队列及磁盘失败仍可能使日志不可见。新包未安装，双端原生与 8 小时验收仍待执行；不得把 0.2.18 的包当作含该修复。
- 0.2.18 在服务端能力协商后可使用独立精简心跳，省略未变化的用户和代理清单，服务端沿用已确认基线；旧服务不支持时客户端使用相同传输身份回退完整心跳。一个用户、一个代理的合成未加密 JSON 从 1756 字节降至 1333 字节，不能外推实际带宽或容量。隔离发压工具新增 `--compact-v2` 覆盖此路径；真实混合部署及原生终端仍需验收。
- 0.2.18 包含此前的过期命令恢复修复：已经处于执行中的命令过期后不会在恢复或重复
  投递时自动执行，保留状态供管理端人工核验；未过期命令仍可恢复。
- 资产首次上报或变化时，同类变更在原事务内批量写入，未变化数据不重写；重复标识及写入中断仍整体回滚。本机隔离 MySQL 单设备 512 条合成更新，三次逐条约 0.27～0.29 秒，批量约 0.05～0.08 秒；不代表轻量心跳稳态或 10 万在线容量。
- 控制端：有界数据库连接池、防重放独立提交和有界清理、采样日志、设备列表
  数据库分页及部分统计读模型；策略全局发布不再逐台分配新版本。批次仍有
  逐台分配版本及限速约束。
- 请求成功聚合在进程空闲时也由现有分钟指标线程刷新上一分钟，减少流量中断时末段数据滞留；计数仍为逐进程内存指标，异常退出可能丢失未刷新窗口，不能代替外部告警或精确分位数。合成请求及线程回归通过；监控采集接入尚待完成。
- 控制 API 失败请求按进程、路由、状态和固定白名单错误码逐分钟计数，每组保留前 5 条详细样本；未知或未标注错误归为 `OTHER`。控制 API 未处理异常按安全元数据另行计数，每组保留前 5 条样本，最多 256 组，超出后合并；管理及后台异常不在此限制内。隔离 MySQL 的相关监控与传输回归 46 项通过、4 项跳过；Windows 无法验证 Gunicorn 原生启动，该项已单独排除。内外层及异常计数不可相加当作终端失败数，异常退出可能丢失未刷新计数，真实风暴日志量、外部采集和告警待验收。
- 当前版本的设备策略详情读取改为显式可重复读快照内的非锁定查询，避免普通管理员查看详情时占用全局策略锁；旧设备状态仍走原有加锁刷新。隔离 MySQL 验证另一事务持有全局锁时有覆盖和无覆盖详情均可读取，并验证读取中发布全局策略时快照一致、过期覆盖刷新及后续版本校验。加入显式快照前一轮设备策略、策略批次及域名策略回归 84 项通过；加入后设备策略 18 项及新增并发场景通过，本地管理员权限 8 项通过。未测量大规模并发或真实管理入口。
- 策略批次创建或恢复前检查版本水位索引为可见、完整的升序 B-tree；维护工具也拒绝同名但不可见或不匹配的索引。隔离 MySQL 验证缺失、隐藏及恢复后的行为；该检查不监测批次运行中被外部更改的索引，也不提高批次速率。
- 策略批次增加默认关闭的高速候选，默认上限仍为每批 20 台/秒；显式提高隔离配置才启用最多 250 台的原子批次。锁定读取版本水位，避免事务旧快照导致分配版本落后；候选包括凭据与协议检查、逐台唯一递增版本、覆盖策略、暂停及降限保护。当前代码本机隔离 MySQL 单次 10 万合成目标创建约 6.924 秒、按工作线程等待规则分配约 51.651 秒，10 万分配版本互不重复；实验不含 HTTP、并发心跳和终端回执，不能证明 120 秒收敛。此前不同机器及缓存条件的一次实验为 18.185 秒和 205.241 秒，不能直接归因比较；详见 [高速策略候选](../server/docs/HIGH-RATE-POLICY-ROLLOUT-CANDIDATE.md)。
