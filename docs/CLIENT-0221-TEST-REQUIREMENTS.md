# Windows / Mac 0.2.21 r2 独立终端测试要求

日期：2026-11-04。配套填写 [测试报告模板](CLIENT-0221-TEST-REPORT-TEMPLATE.md)。
本清单汇总已有交接要求，不改变冻结的安装包、脚本或验收结果。

## 交付对象和环境

| 对象 | 本轮使用材料 | 要求 |
| --- | --- | --- |
| Windows 10 x64、Windows 11 x64 | 0.2.21 r2 MSI 与独立验收工具 | 两种系统分别原生执行；Windows 不签名是确认要求 |
| macOS Apple Silicon、Intel | 0.2.21 r2 无凭据源码包 | 两架构分别构建、正式签名、公证、原生执行，不能用 Rosetta 代替 Intel 原生 |
| 控制端 | 实际测试时记录版本、schema、能力开关和测试窗口 | 默认关闭的功能未启用时记 BLOCKED 或 NOT-APPLICABLE，不能记 PASS |

每种环境至少有真实干净首装和已有旧版本升级两条证据。可以使用独立设备，或在本轮安装
成功、卸载和配置恢复得到验证后复用设备；不得通过删除用户配置、设备身份或数据库伪造
干净环境。已有旧 Go 与 .NET 两条升级路径分别记录；缺少某条基线时明确列为未覆盖。
系统版本须写到构建号，另记 CPU 架构、内存、磁盘可用空间及各业务应用版本。
报告用设备别名，真实设备 ID/SID、用户名、路径和对应关系留在本地受限记录。

## 测试顺序和判定

统一使用 PASS、FAIL、BLOCKED、NOT-RUN、NOT-APPLICABLE 五种状态。后三种写明原因；
FAIL 写明复现步骤和影响。工具的 `phase-passed`、`observation-completed` 和 `passed`
分别有范围限制，不直接等于整机验收通过。无法判定时保留待核查，不填 PASS。

| 编号 | 测试 | 必须保留的证据与通过条件 |
| --- | --- | --- |
| PKG-01 | 包与平台核验 | 最终包和服务程序摘要、架构、版本；Windows 如实记录 NotSigned；Mac 正式程序/安装包签名、公证票据、Gatekeeper 通过，包内不含凭据 |
| LIFE-01 | 干净首装 | 安装前基线、安装退出码、服务启动、18080 由该服务拥有、健康接口、控制台在线及版本一致；IOA 投递成功不能代替这些检查 |
| LIFE-02 | 旧版本覆盖升级 | 写明原版本和实现 Go/.NET；设备身份保持、策略/路由/凭据及配置备份保留，无重复服务和代理端口抢占；旧状态可正确读取 |
| LIFE-03 | 同包修复、重复安装 | 操作退出码、服务及身份前后一致，无重复路由或配置持续叠加；3010 先记待重启，重启核对后才能关闭 |
| LIFE-04 | 真实重启与多用户 | 操作系统实际重启后自动启动；普通交互用户可使用，服务账户权限正常；第二用户隔离，不误改其他用户配置或导出凭据 |
| LIFE-05 | 卸载、恢复与重装 | 服务移除、18080 释放、原业务配置与原厂直连恢复；安装后用户修改不被旧备份覆盖；存在冲突时明确报告并保留备份，不能强制覆盖；随后同包重装可用 |
| LIFE-06 | 企业分发 | Windows IOA/SYSTEM 静默安装与检测退出码、目标交互用户绑定、重启状态；Mac 若计划 IOA 分发也须实测，不以本地管理员安装代替 |
| APP-01 | 真实业务和 SSE | 按下列应用矩阵逐项记录。至少三次短对话和一次持续流式响应，含用户取消；成功结束、取消后资源释放及上游错误传播正确，无卡死或静默截断 |
| ROUTE-01 | 路由与配置恢复 | 原厂/网关、精确地址白名单、启用的域名白名单与地址分流；用脱敏请求关联证明走了预期入口；Qoder 只发现，不写非公开 BYOK |
| CTRL-01 | 策略发布与校准 | 每设备至少三轮安全的测试策略变更并恢复原策略；记录下表三个 UTC 时间、策略版本及校准结果，不能只看“已接收” |
| CTRL-02 | 远程暂停与恢复 | 每设备至少三轮；保留命令关联号、执行回执和真实业务前后行为；单纯将策略 enabled 设 false 不等于远程暂停命令 |
| CTRL-03 | 资产和轻量同步 | 支持协商时验证未变化清单保留、变化后更新、工号显示正确；重启后身份和资产不丢失；旧协议设备仍能完整上报 |
| OFF-01 | 控制端失联与恢复 | 仅阻断该测试终端的控制连接，保持网关/原厂业务所需连接；有效缓存继续使用；正常重启后仍可用；恢复后自动同步，不清库、不重注册 |
| QUEUE-01 | 事件积压观测 | 记录 controlEventQueue 字段和恢复时间线；持久容量 1000，内存恢复合并可暂达 2000；读取失败为 null/unavailable，不是零。核对本设备合成事件 ID 去重和到达，计数相等不能证明无损 |
| SOAK-01 | 原生已安装服务连续 8 小时 | 有真实业务活动及连续资源/健康采样，记录睡眠、重启、异常、错误和队列；安装后长期闲置截图不能代替此项 |
| SOAK-02 | 最终包内二进制的合成 8 小时 | 使用独立合成工具和临时数据；普通请求、SSE、缓存、计划重启及错误记录齐备；不能替代 SOAK-01 或控制端容量验收 |

应用矩阵覆盖计划推广的 Claude、Codex CLI、Codex Desktop、CC Switch 管理的入口、DSH
及 Qoder 发现。每项记录实际版本、平台、是否启用及上述请求结果；DSH 不使用时写明
未启用，其通过结论不得外推到 DSH。暂不具备某应用时列明覆盖缺口。
使用无敏感内容的测试对话；报告只保留预期结果、是否完整及脱敏关联号，不提交原始对话。

CTRL-01/02 每次分别记录：

1. T0：管理员发起发布或命令的 UTC 时间。
2. T1：终端执行/校准结束时间。
3. T2：控制端收到最终回执并可见的 UTC 时间，结论使用 T2−T0。

先校对终端与控制端时钟。正常在线、服务健康的本次样本以 120 秒作为目标；超时、校准
失败或缺回执不能计为成功。独立几台机器的样本只证明本次行为，不能证明总体 99% 或
10 万在线收敛。请求关联号在回传中使用一致别名，保留本地真实映射以供定点复核。

## 长稳如何执行和回传

Windows 安装和阶段脚本按 [Windows 交接](WINDOWS-GO-0221-HANDOFF.md)执行，
保留 Prepare、Install、Codex、Paused、Resumed、AfterReboot、Uninstall 各次生成的
`sanitized-report.json`。同一目标用户 SID 与输出目录贯穿全程；SID 本身不放进回传报告。

已安装 Windows 服务使用 `Observe-WindowsSoak.ps1` 的默认 8 小时模式。回传生成的
`summary.json` 和完整 `samples.jsonl`。确认 `duration8hCompleted` 与
`samplingContinuityValid`，但仍须检查异常和趋势。`-SmokeSeconds` 只验证工具。
该工具只观察，不产生业务流量；另按 APP-01 在开始、中段、结束安排正常业务，记录
各窗口的请求量和成功/失败，不通过修改系统时钟凑满时长。

Windows 合成测试按 [合成长稳](WINDOWS-GO-0221-ACTIVE-SOAK.md)执行；
Mac 构建、公证、包检查及合成测试按 [Mac 交接](MACOS-GO-0221-HANDOFF.md)执行。
两者回传 `soak-report.json`，以及工具实际生成的进度和完整时间线文件；报告的
`binary_sha256` 必须对应最终包内程序，`duration_8h_completed` 为真且覆盖完整时长。
先短测再正式 8 小时，每次用新输出路径。合成工具占用 18080，须在本轮安装前或
本轮已验证卸载后的独立测试窗口运行，不能为抢端口停止别人的业务服务。

Mac 的 `validate_go_pkg.py` 标准输出 JSON 另存为 `package-validation.json`，记录退出码。
它不执行安装。当前未提供 Mac 已安装服务的原生只读观察器：团队须用获准的只读工具
每 30 秒采样实际服务 PID、存活时长、CPU 时间、RSS、线程/文件句柄、健康和队列状态，
附采样命令/工具版本及完整时间线，不能拿合成进程结果替代 launchd 服务结果。

原生长稳采样应覆盖至少 28800 秒，目标每 30 秒一次；报告采样数、最大间隔、重启与
休眠记录。大于 90 秒的缺口、工具中断或时钟跳变须解释并重新安排连续测试，不能直接
计为通过。记录 CPU、内存、句柄、线程、磁盘/日志、捕获和队列的首段/尾段、峰值及趋势，
不能只提交平均值。原生安装服务观察窗口避免混入生命周期重启测试；计划操作另列时间。

不得出现无法解释的业务中断、崩溃、持续资源增长、配置恢复失败或队列持续不可读。
出现后保留现场、停止扩大测试范围，提交 FAIL 和证据；不能靠定时重启、清队列或
删状态库使曲线好看。尚无统一的绝对 CPU/RSS 阈值，须结合测试请求量和原机基线审查，
不能自行把“最后一次健康”视为资源稳定。

## 条件性专项与灰度服务范围

设备绑定 HTTPS/V2、Ed25519、公钥固定、schema 6 两阶段凭据轮换、响应丢失、执行中
命令崩溃恢复等专项，必须先有独立测试数据和可回滚的测试入口。按
[补充验收](CLIENT-0221-ADDITIONAL-ACCEPTANCE.md)执行。当前 HTTP 且默认关闭的能力
不要求在灰度服务上强开；报告列 BLOCKED 或 NOT-APPLICABLE，并保留后续专项门禁。

2026-11-04 用户已授权在现有灰度 Linux 服务器受控升级和测试。实施时先核实当前
账号/服务/版本和资源，备份并在独立目录、端口及数据库副本验证恢复迁移，再切换灰度
服务和做小范围功能及长稳观察。此安排无需另配服务器，但副本不连接真实业务库写入。
现有升级门禁不因授权自动变为已验证；不得仅将 `MUTATION_VALIDATED` 改为 True 放行。
10 万在线压测、共享数据库断连和磁盘耗尽不混入运行灰度业务的验证窗口。
本清单发布时远程工具尚未加载，未发生服务器连接、升级或测试。

## 最后交回什么

每种系统/架构一个报告目录，建议命名 `WIN10-X64-A`、`WIN11-X64-A`、`MAC-ARM64-A`、
`MAC-X64-A`。从模板复制 `REPORT.md`，附环境与包信息、逐项结果、控制时间表、资源
汇总和未关闭问题。每个结论引用附件的相对文件名，截图附时间和用例号。

```text
CLIENT-0.2.21-ACCEPTANCE/
  INDEX.md                        # 四种平台状态与缺口，不能把 BLOCKED 算 PASS
  WIN11-X64-A/
    REPORT.md                     # 填写的测试报告模板
    package-info.json             # 版本、最终包/程序摘要；不含凭据和本机真实路径
    phases/                       # 每次 sanitized-report.json，保留阶段/次数对应关系
    installed-soak/               # summary.json、完整 samples.jsonl 或 Mac 只读采样
    synthetic-soak/               # soak-report.json、实际生成的时间线及进度文件
    control-results.csv           # 用例、设备别名、版本/命令别名、T0/T1/T2、耗时、结果
    screenshots/                  # 经审查且裁去真实账户/地址/正文的必要截图
    issues/                       # 每个 FAIL/BLOCKED 的脱敏复现记录
  SHA256SUMS.txt                   # 所有回传文件的摘要（不对自身求摘要）
```

其余平台采用同样结构；Mac 增加 `package-validation.json` 和签名/公证摘要结果。
不要求回传 PKG/MSI、原始安装日志、捕获正文、SQLite/数据库备份、机器密钥、Token、
API Key、Apple 私钥、用户配置或 `prepared.json`。自动输出也须先审查，必要时脱敏；
对脱敏后的最终回传文件计算摘要，并注明发生过脱敏，不把其哈希当成原始证据哈希。
原始材料和别名映射留在团队受限环境，出现问题时再定点核查。

我会按最终包一致性、平台覆盖、生命周期、业务/SSE、回执时间、完整 8 小时及资源趋势
逐项复核；输出各平台“通过 / 不通过 / 材料不足”的结论及缺陷清单。仅有截图、
测试人员口头通过、单一 passed 字段或没有时间线的 8 小时结论，都不能关闭门禁。
