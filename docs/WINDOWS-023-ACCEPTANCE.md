## 接口与兼容边界

- `--exclude-codex` / `SF_PROXY_EXCLUDE_CODEX` 默认 `false`，命令行优先。
  开启时自动接管、管理 attach 和远程启用不改写 Codex 或 CC Switch 的 Codex 项。
  暂停及卸载仍恢复程序自己已经接管的配置，不能遗留不可用路由。本机测试前确认没有既有 Codex 路由。
- Go 构建必须显式提供 `-GatewayOrigin`，拒绝占位地址；`-EnableDSH` 默认关闭。
  最终 MSI 不嵌入本机 Codex 排除设置，独立终端仍验证默认完整行为。
- Desktop `0.2.1-rc.2` 仅扩展账户模式的 canonical `desktop` profile。
  使用已安装包身份、内嵌账户插件版本和实际运行的完整宿主参数验证来源；只有主进程而无宿主不接管。
  未识别 Node 的通用 CLI 检查不完整标志保持上报，不代替已验证宿主的来源判定；
  已确认的 DSH 未知覆盖层、宿主未知参数、非空基础配置、未知插件及歧义 patch 仍拒绝接管。
  既有 alpha.5 API Key 支持不因此扩展到 rc.2 的其他 provider 或 pi-ai 版本。
- 账户模式在 `127.0.0.1` 为每条路由保留独立 origin，主代理仍为 18080。
  origin 保存在既有路由字段，重启必须重新占用原端口；占用冲突明确失败，不静默换地址。
  `/models` 和 `/anthropic/...` 经同一路由转发，账户插件的 `inferenceOrigin` 与 LLM 的 `baseURL` 一致更新。
- 不改 DSH 程序包、登录平台地址或凭据存储，不放宽其认证规则。
  两个配置行的原始状态和接管状态保存在受保护的恢复日志；用户改动受管行后拒绝覆盖并保留恢复证据。
  `x-dsh-auth-token` 沿用敏感头脱敏，不能进入捕获头、运行日志或公开报告。

## 发布门禁

本机不自动重启。用户已授权必要时经 i-jumper 修复指定控制端；本次复测通过，未执行远程变更。
账户认证、AgentType 11、网关路径或文件操作不兼容时阻断发布，
不能改用 API Key 模式或纯合成结果替代真实账户验收。
静默命令为 `msiexec.exe /i "<最终 MSI>" /qn /norestart`；0 成功，3010 记录待重启，其余返回码不记为成功。
内部未签名候选只保存在受限目录；全部证据齐全后交付同一已验收 MSI 及最终 SHA-256，不再重新构建。

四小时门禁最后两小时保持固定负载且不重启。四个半小时窗口 RSS、Private Bytes 中位数波动需不超过
`max(8 MiB, 10%)`，句柄及线程数不得持续增长；不满足时延长至八小时，仍增长则失败。
已有其他平台四小时结果不能记为 Windows 原生通过。

Go MSI 在 InstallInitialize 后先执行回滚登记与停服快照脚本，通过提前的 InstallExecute 执行，
随后卸载旧产品，再进入 ProcessComponents 和新文件安装。此顺序避免 ICE63，保留同一 MSI 事务内的恢复；
静态序列校验必须验证上述实际表顺序，原生故障回滚仍待验。

Windows Installer COM 的 Execute/Close 返回值显式丢弃，避免空返回值混入版本和表行查询；
查询记录及视图显式释放。原生 PowerShell 5.1 已对 r4 MSI 复核版本、事务序列和五项载荷清单通过。
管理员只读基线的在线 SQLite 备份完整性为 ok，所有历史 Codex 路由数为 0；
该在线数据库备份不代替停服后一致性快照和恢复演练。

升级辅助程序从停服前快照保留非控制端服务环境变量，以处理旧产品卸载导致服务注册键删除的情况。
当前服务中显式给出的同名设置优先（不区分大小写）；旧控制端覆盖变量仍移除。
Codex 排除和网关 HMAC 的删除服务键回归使用合成值，不导出真实密钥。
0.1.22 停服快照与恢复演练已通过：26 个备份文件逐项摘要一致，旧二进制与 Codex 配置未变，服务恢复健康。
这不是 MSI 故障回滚通过证明。用户确认的 Codex model 字段调整已保留并单独建立保护基线。

原生 SYSTEM 合成 DPAPI 已通过：用户 .NET→SYSTEM Go、用户 Go→SYSTEM .NET、
SYSTEM .NET→用户 Go、SYSTEM Go→用户 .NET。单次 SYSTEM 计划任务退出码为 0，任务已清理。
构建失败报告仅补充源文件名和行号，不记录凭据或原始异常正文。

原生 r7 升级在预定注入之前的 verify_service_path 失败：旧 .NET PE 文件版本 0.1.22.0，
Go PE 无文件版本；MSI 将新服务组件计划为 Action: Null，导致旧服务卸载后没有创建新服务。
Go MSI 仅在 WIX_UPGRADE_DETECTED 时、CostInitialize 之前临时设置 REINSTALLMODE=amus，
仅对该包正常选择的载荷使用强制覆盖规则；不在 Property 表永久设置，不伪造 PE 文件版本。
静态验证要求该规则，实际受控回滚与正常升级仍须用新 MSI 重验。
r7 自然失败后，旧 0.1.22 注册、旧二进制摘要、服务健康与 Codex 配置均确认恢复；这不等于预定故障点通过。
重新打包可复用 r7 已通过全量 Go 测试和 vet 的逐字节相同 Go 载荷，必须同时记录载荷源码提交、
安装器源码提交、原 MSI 和每个载荷摘要，并证明 go-client 树未变；MSI 本身重新冻结、重新验收。
