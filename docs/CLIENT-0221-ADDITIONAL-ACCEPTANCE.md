# 0.2.21 客户端补充验收

## 本轮增量：控制事件队列观测

`/healthz.controlEventQueue` 提供 `memoryDepth`、`persistedDepth`、`capacity`、
`memoryBaselineLoaded` 与 `persistedReadStatus`。只读取队列行数，不返回事件正文；
`capacity` 是持久队列上限；读取恢复时合并最多两份队列，内存深度可能暂时达到 2000，
由原有每批 100 条的发送路径逐步排空，不能把它误当成无效采样。
单次最多计数 1001 行来识别超过 1000 上限的异常状态，查询使用一秒上下文预算。
读取失败时持久深度为 `null`、状态为 `unavailable`，健康接口返回 503，不能当成空队列。

合成长稳时间线的 `control_event_queue` 和 Windows 只读观察的 `controlEventQueue`
仅保留这些经过类型与范围检查的字段。旧版缺失或无效数据记录为 `null`，不能补零或
据此认定队列健康。内存和持久计数是相邻采样点，不应相减作为丢失数；计数相同也不能
证明事件内容一致、已经成功上报或每条都已持久化。

在独立终端和隔离控制服务上观察离线事件积压、正常重启、恢复连接和上报后清空；核对
两类时间线的计数与读取状态，记录是否持续增长、溢出或不可读。不得通过删表、清库或
破坏真实 SQLite 来构造故障。本机模拟写入、重开 SQLite、成功回执及计数读取失败
已有定向回归，但不代替原生服务账户及 8 小时验收。

## 已包含的设备凭据两阶段更新

本候选保留 0.2.20 的受保护待轮换记录，以及 Token、设备传输密钥和待轮换记录的原子提交。
只有固定服务端公钥的 HTTPS、设备传输 V2、完整状态存储和服务端明确协商同时满足时，
才会准备新凭据；当前生产 HTTP 配置不会启用。待轮换状态存在时禁止自动重新注册。
经校验的人工凭据恢复会在同一事务内清除旧传输绑定和待轮换状态，随后重新协商。

隔离控制端必须先部署匹配源码，停服激活可选 schema 6；该激活不能直接降回 r75 或
更早服务。详见服务端源码包中的 `docs/CREDENTIAL-ROTATION-CANDIDATE.md`。
没有隔离控制服务时本项标为受阻，不能在现网切换 TLS、迁移 schema、提前更换凭据或
删除状态来构造验收。

具备隔离条件后，在独立 Windows/Mac 服务账户下验证受保护状态写入、准备或提交响应
丢失后的服务重启、准备过期、停用新准备、吊销和人工恢复；检查恢复后 Token 与传输
身份一致、旧凭据按重叠期限失效、没有自动重新注册，以及有效缓存下本地业务持续可用。
凭据到期使用服务端时间，默认至少 30 天；缩短时间或构造故障需另行批准的隔离方案。
回传最终包摘要、脱敏阶段和结果，不回传 Token、密钥或整个状态库。

本机跨语言测试使用合成 HTTPS、MySQL 和文件密钥保护器，不能证明 Windows 服务账户的
DPAPI 或 Mac 安装权限行为。本轮不提供设备独立私钥、硬件证明或整个状态库的防回滚。

旧客户端不会恢复本轮新增的待轮换记录。启用轮换后，客户端回退须先关闭新准备、确认
目标设备待轮换全部完成，或执行已验证的人工凭据恢复；无法确认时继续向前修复，不能
直接降级后删除待轮换记录。服务端 schema 6 的回退限制另行适用。

本清单补充同一交付包中的 Windows 独立终端或 Mac 构建及验收步骤，不能替代其中的安装、升级、
卸载、IOA、原生架构和真实业务检查。使用最终包摘要记录每一项结果；Windows
包未签名，Mac 需先完成签名及公证。以下涉及控制端或故障注入的步骤只在独立
终端、隔离控制服务及合成测试数据上执行，不要对生产环境实施故障注入。

## 新策略的校准与回执

1. 确认测试设备在线，记录设备 ID、客户端版本、当前策略版本、控制端时区及
   采样时间。准备可以安全回退的合成策略，不使用停用策略来模拟远程停用。
2. 记录发起发布请求的时间，发布新版本并记录服务端确认时间。观察终端的
   `POLICY_APPLIED`、校准结果、控制台的目标版本及应用状态，记录控制端首次
   显示校准成功或失败的时间、错误码；按批准的回退步骤恢复原策略。
3. 计算从发起发布到控制端收到终端校准结果的时间。运行中途断线、校准失败或
   没有回执应记录实际现象，不算成功。单台终端通过不能证明 99% 的 120 秒目标。

0.2.10 及后续版本在新策略触发的校准结束后安排错峰补报；心跳失败退避、实际
校准时间、网络与服务端负载都会影响观察时间。控制端显示已接收不等于已校准。

## 离线事件与恢复

1. 先确认有效缓存和真实业务正常。记录测试窗口与设备 ID；在获准的隔离网络中
   暂时阻断该终端到隔离控制服务的连接，保持终端本地业务所需的其他连接。
2. 等待出现控制同步失败，记录脱敏时间及错误码，按平台正常方式重启服务或
   终端；检查有效离线缓存及业务是否仍可使用。不要删除状态、修改数据库或
   重新注册设备。
3. 恢复隔离控制连接，观察心跳及事件上报恢复。由有权限的隔离数据库操作人
   只读核对该测试设备和时间范围内的 `endpoint_events`：按 `event_id` 核对
   `CONTROL_SYNC_FAILED` 是否最终入库，记录事件时间、接收时间和去重结果。
   数据库查询范围限定为合成设备；不得导出完整事件正文或凭据。
4. 检查是否出现 `EVENT_QUEUE_WRITE_FAILED`、`EVENT_QUEUE_READ_FAILED` 或
   `EVENT_QUEUE_OVERFLOW`；存在错误、溢出或事件未入库时记录失败或待分析，
   不以重新注册或清空队列代替恢复验证。

启动读取队列失败后在进程内恢复的分支已有本机合成测试；目前没有可安全复用的
原生故障注入方法，不能要求验收人员破坏 SQLite 文件。若隔离测试团队具备经批准、
可回滚的方法，可另行验证并保留证据；否则该原生故障注入项标为待验证。

## 配置发现失败与兼容

0.2.11 对用户配置发现失败记录 `PROFILE_DISCOVERY_FAILED`。如果服务端已协商
轻量心跳且有上次确认的完整资产快照，客户端尝试保留快照继续心跳；恢复后继续
尝试完整扫描。旧服务端不使用未协商的轻量路径。本机已使用合成故障和隔离
MySQL 验证口径，但原生平台仍待验证。

在具备经批准、可恢复的隔离故障注入手段时，分别验证错误码、失败状态、资产
未被清空、恢复后完整扫描及成功状态；同时验证旧服务端不会收到轻量请求。
没有安全注入手段时记录待验证，不要修改其他用户权限或破坏真实配置来制造故障。

回传最终安装包 SHA-256、系统版本与架构、阶段结果、脱敏时间线及错误码。原始
请求正文、密钥、客户端凭据、数据库导出和未经审查的日志或配置备份留在受限环境。

## 过期执行中命令

0.2.21 对已持久化为执行中、恢复时已过期或无可靠到期时间的命令不自动再次执行。当前交付的合成长稳控制助手不支持安全构造该故障；需要独立终端、隔离控制端和经批准的可回滚故障注入方案。构造执行中后中断客户端，等待命令过期并恢复，核对客户端没有重执行、控制端结果未知及人工核验流程。没有上述条件时标为待验证；不在现网构造命令、修改状态数据库或重注册。Go 合成测试通过不能替代原生验收。


## 重注册响应丢失验证

本版本在已保存原设备 Token 的情况下，请求支持该能力的候选控制端保留 Token，避免响应丢失后凭据失效。仅在隔离控制端上验证：先保持客户端本地凭据，构造带有效原 Token 的重注册并丢弃第一次响应，重试后确认原 Token 仍可认证；无效或已吊销 Token 必须拒绝。不得在现网清除设备状态或人为更换凭据。0.2.21 还会在首次注册前持久化随机设备凭据，并在支持该能力的候选控制端上复用该凭据重试。旧控制端不理解该字段，首次响应丢失时仍不能自动恢复；须先部署并验证新控制端。实际原生端到端故障注入尚未验收。


## 设备绑定封装验收边界

0.2.21 包含两代默认关闭的设备绑定封装候选。V2 使用服务端独立主密钥和设备验证值派生每台设备密钥，客户端只在固定服务端公钥的 HTTPS 上主动声明能力并接受；当前 HTTP 交付配置不会启用。隔离验收需覆盖新旧服务端密钥重叠、逐批切换、不降级、令牌撤销与恢复、断网、重启及回滚。客户端会以平台保护机制持久保存密钥代号、设备密钥和令牌摘要，重启后继续使用；恢复失败、证书固定值或令牌变化会阻止控制连接，业务侧仍使用有效离线缓存。该机制无法防止有权限者删除或回滚整个本地状态库；受控恢复流程尚待验收。服务端主密钥与数据库验证值同时泄露、密钥配置不一致、旧密钥提前删除和额外数据库负载仍需专项评估。V2 是集中主密钥派生，不是设备独立私钥或硬件设备证明。

旧 .NET 客户端不支持 HTTPS 与原 AES 封装组合；必须保留兼容的旧 HTTP 路径并规划退役，不要直接迁入新入口。不得在现网清库、重注册、修改 TLS 或盲目删除旧密钥来代替隔离验证。


首次注册恢复需搭配支持 `initialDeviceToken` 的候选控制端；服务端先在隔离环境验证，再考虑按既定流程部署。旧控制端可继续服务，但无法保证首次注册丢失响应后的自动恢复。


## 精简心跳兼容验收

0.2.21 在服务端明确宣告支持后，通过独立精简心跳接口省略未变化的用户和代理清单；服务端保留上次确认的清单。旧服务返回未支持时，客户端使用原有加密身份重新发送完整心跳。隔离验收应覆盖新旧服务混合、服务回退、设备绑定封装、控制端重启、清单变化和正常活动更新，并核对用户、代理与端点没有丢失。若出现资产缺失、错误或重试尖峰，暂停推广。正式环境未启用前不得将本地模拟测试当作完成验收。
