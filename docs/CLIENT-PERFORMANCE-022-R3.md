# 0.2.2 r3 性能与四小时结果复核

核查：2026-10-18。程序摘要与五轮性能、四小时报告及流水线一致，未更换二进制。正文 Sync、逐条摘要写穿及生产捕获设置保留。

## 延迟门禁

## 资源与长稳

五轮负载 RSS 中位数：Go 29.58 MiB、.NET 197.28 MiB；负载单核 CPU 占比中位数：Go 16.04%、.NET 47.04%。这些是本机合成负载下的进程统计，不能替代空闲内存、Windows 或生产设备指标。

四小时实际 14419.34 秒，23,040 请求，3 次重启；915 次心跳，身份及凭据保留，配置接管/恢复、DSH、请求头/编号关联和过期证据清理通过。23,040 条捕获均 SUCCESS，无退化；所有测试子进程已清理。

RSS 全程 26.84–60.42 MiB，但不能记为“内存无增长”：末次重启的首/末四分位中位数从 45.23 增至 55.78 MiB；保留捕获文件增至约 23,000 个。维护目录扫描随文件数量分配是合理候选原因，现有证据不能证明根因或平台期，不能据此宣布资源长稳门禁全部通过。磁盘最终约 49.45 MiB，增长包含按设计保留的捕获，已验证过期项删除；没有达到容量上限测试。

新增诊断日志独立 +1 ms / CPU +1 个百分点 / RSS +8 MiB 预算仍待隔离 A/B；整体 .NET 对比不能证明该单项归因。原生 Windows IOA、Mac root/跨 UID、真实 Intel 及正式签名发行仍待验。
