## 已实现

|---|---|
| 跨日摘要静默丢失 | 生命周期锁覆盖 open/write/close、压缩与删除；活动日期及待发布正文保护。原复现修前 5/5 失败，修后 race 10/10 通过。摘要最多两个持久写穿句柄，锁外编码单次写入，正文 Sync 保留 |

| Mac ACL 丢失 | 纯 Go Darwin 原生 ACL 与全部扩展属性复制/核验、owner/mode 保留、元数据并发检查；失败不发布。接管和恢复使用同一路径 |
| 命令终态回执不幂等 | 控制端同设备/命令/终态/结果重复返回 202，不改首次完成时间；冲突仍 409。客户端永久冲突结束自动重试，保留本地回执与诊断 |

| 压缩争用 | 单维护消费者、有界提示队列和积压；新文件延后 2 秒，繁忙时老于 60 秒才逐个压缩，空闲有界批次，分钟扫描恢复重启/丢提示积压 |

## 直接覆盖升级是默认路径

Windows 使用既有 UpgradeCode `643CFDA1-3A12-4C57-BD65-5F6106CBAB90`、服务名 `SfEndpointAIProxy` 和 `%ProgramData%\SF\EndpointAIProxy`。已核对旧 C# 0.1.20/0.1.21/0.1.22 交付源码使用同一身份，升级时跳过普通卸载的解除接管。MSI MajorUpgrade 在事务内完成旧产品替换，用户无需手动先卸载。

安装流程补强为：预检 → 保存原服务/注册表配置 → 停服 → 一致性状态与恢复日志快照 → MSI 替换 → 新程序验证 → 提交。数据库指纹覆盖身份、路由、凭据解密、策略、运行状态与命令回执；首次启动前严格比较，健康响应绑定原设备 ID，验证实际程序路径、端口所属进程和稳定窗口。控制面离线仍允许本地安装就绪。

**安装提交前的新 Go 服务由数据根下 `.installation-pending` 暂停配置接管、控制同步及远程启停。** 原有路由仍可提供代理，防止安装失败后残留新接管配置或覆盖安装期间新收到的命令。提交删除本事务标识后正常恢复，无需重启程序；失败恢复旧状态及服务，再核验旧程序摘要、健康与设备身份。异常保留受保护恢复证据。成功回退后将事务归档到 `InstallerState/Recovered`，释放活动事务，允许同包后续再次尝试；未完成恢复继续阻止覆盖。安装提交恢复业务之后，清理失败仅保留证据，不再触发旧状态回滚。非默认旧数据根会在停服前拒绝，避免把另一状态库误当成已迁移。

同版本不同 ProductCode 的包在 MSI 内由 LaunchCondition 拒绝；同一个已安装 MSI 可显式修复，不进行重复产品注册。发布包保持不可变，内容变化需递增版本。默认 `/i` 重复安装不触发停服自定义动作，显式 `/fa` 修复走完整事务。

Mac 沿用原 PKG 标识与 LaunchDaemon。停服后备份 state（含机器密钥）及 config-backups；原程序和服务配置使用既有快照。启动前核对保留内容，SHM 是可重建协调文件，不作持久业务字节等同性判据；读取 SQLite 身份在快照前执行。Go 安装同样使用提交前保护标识，失败回滚并验证原身份，不先运行卸载工具。

## 一键升级与备用重装

源码包根提供 `Upgrade-Client.cmd`，内部为 Windows PowerShell 5.1 脚本。Windows 构建输出同步提供脚本、辅助程序及校验文件。

```powershell
.\Upgrade-Client.cmd -MsiFile C:\Secure\EndpointAIDLP-Client-0.2.2-go-win-x64.msi
```

默认 `-Mode Upgrade`，校验新包 SHA256、MSI 产品身份、版本和 x64 架构，执行直接覆盖；同一 ProductCode 使用 `/fa` 修复。未知错误绝不自动转为卸载。校验/测试脚本从实际 MSI 读取目标版本，解决旧默认 0.2.0 误拒绝新包的问题。

只有确认标准覆盖不适用且具备原版恢复材料时，才使用：

```powershell
.\Upgrade-Client.cmd -Mode Reinstall -MsiFile C:\Secure\new.msi `
  -RollbackMsi C:\Secure\original.msi -OutputDirectory C:\Secure\MigrationEvidence
```

重装只接受已识别的 0.1.20/0.1.21/0.1.22/0.2.0/0.2.1 来源；验证原版 ProductCode/版本、辅助程序完整性后停止备份、正常解除接管和卸载、在新服务启动前恢复受保护状态，再安装和核对。不是仅保留数据目录，也不强删注册表、服务、密钥或配置。未知版本/损坏注册需先处理，不自动卸载。

退出码 3010 单独记录重启要求；重装重启阶段可用相同参数和相同 OutputDirectory 继续。MSI 事务内安装失败可恢复原包；**新 MSI 已提交之后**发生外层健康异常，业务可能已恢复，此时保留候选和状态并报告 recovery-required，不再盲目用旧快照覆盖新回执或强行降级。恢复失败保留现场；原始安装日志和快照仅在受保护目录，不能公开上传。

上述 Windows 行为目前为源码与交叉编译/静态校验结果，**仍须 Windows 管理员、SYSTEM 与 IOA 原生验收**，不能据此宣称所有 PC 已保证覆盖成功。

已通过冻结候选全量 Go race/vet、三架构构建、真实旧 C# ↔ Go 密文/SQLite 状态双向互读；ARM64 与 Intel Rosetta 的固定真实 DSH SDK 18 场景及配置恢复通过。Mac 原生 syscall/ACL/xattr 与 DSH 回归通过；安装脚本隔离测试现为 37 项通过，覆盖提交保护、启动失败恢复、数据库变化拒绝、SHM 差异和提交后清理失败不回滚。

### r3 性能与四小时功能门禁已通过

同一 r3 签名程序完成五轮交替 .NET/Go 对比，每场景至少 1,000 次测量请求，覆盖并发 1/8/32、JSON/SSE/64 KiB 和 direct 控制组。45 个配对场景均满足相对 .NET 的 +5 ms 门禁；最差增量 -0.084417 ms。两端各 60,440 条捕获完整、无退化，正文 Sync 和逐条摘要写穿保留。

随后四小时功能长稳实际运行 **14,419.34 秒**，完成 **23,040 请求、3 次重启、915 次心跳**，捕获全 SUCCESS、无退化，配置恢复、身份/凭据、DSH 和请求 ID 关联通过。性能/长稳/流水线/当前签名程序摘要一致，子进程已清理。证据使用 `performance-stable-022-20261018-r3.json`、`soak-4h-022-20261018-r3.json` 和 `verification-pipeline-022-20261018-r3.json`。

### 性能复测发现并修复 SSE 截断

首次正式性能执行中断，经缩小测试确认旧 Go 0.2.1 与候选 r2 均存在 HTTP/1 并发 SSE 竞态：首次响应 Flush 默认关闭入站请求体，与 Transport 尚未完成的请求长度检查竞争，导致本地主动关闭上游连接。模拟上游直接访问正常；不含捕获的代理测试也能复现，排除捕获压缩作为必要条件。连接关闭栈指向 Transport.writeLoop，新增门闩回归能确定性触发截断。修前失败证据 `sse-beforefix-022-20261018.txt` 保留；启用 ResponseController.EnableFullDuplex 后，确定性回归和并发回归 race 10 轮通过，另有并发回归 race 20 轮通过。该修复不重试已发送请求、不缓冲 SSE，不改变正文或摘要持久化。

最终候选改为 `0.2.2-20261018-r3`，r2 构建、签名、PKG 和第一次 Windows ZIP 是修复前材料，**不能作为最新交付或继续使用其性能结论**。新正式性能证据使用 `performance-stable-022-20261018-r3.json`；历史 0.2.1 Go 参考失败会如实保留并停止比较该参考，.NET 与新候选五轮门禁仍完整执行，任何候选失败仍中止。长稳使用相同 r3 签名程序与独立 r3 文件。
