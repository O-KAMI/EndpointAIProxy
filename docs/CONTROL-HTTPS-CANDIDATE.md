# 控制传输 HTTPS 候选

0.2.7 客户端可在 HTTPS 上继续使用现有加密信封；已有 HTTP 凭据格式仍受支持。
该能力尚未在现网启用，服务端 TLS 入口、证书和隔离环境端到端验证均待落实。
不要将其视为设备级传输凭据或共享密钥轮换的替代方案。

HTTPS 凭据沿用现有字段，并将 `origin` 设置为 HTTPS 地址，增加
`certificateSpkiSha256`：值为服务端叶子证书 RSA 公钥 SubjectPublicKeyInfo 的
SHA-256 摘要的标准 Base64 编码，即解码后 32 字节。客户端检查固定公钥、主机名
及证书有效期；证书或公钥更换需提前制定迁移与回退方案。HTTP 凭据不包含该字段。
实际证书指纹必须从受信任渠道核对，不要把真实凭据放进源码包或验收报告。

服务端 [Nginx 示例](../server/deploy/nginx-local-admin.conf.example) 同时示例
HTTP 和 HTTPS 入口；必须按实际证书、域名、权限及代理拓扑配置，在隔离环境
进行 `nginx -t`、握手、业务回执和回退验证。该文件不表示生产已有此入口。

现有设备的身份绑定包含控制地址和证书固定值。改变两者可能使既有凭据不再被
自动采用，必须先验证受控的管理员凭据恢复流程；不要依赖清除状态或重复注册。
原 HTTP 路径需要在已验证的过渡期保持可回退。不得据此声称无缝迁移或推广通过。
